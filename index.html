Security for AI coding agents.

OpenMoat checks every command, file access, web request and MCP call your coding agent makes, and blocks the dangerous ones before they run. Everything else it leaves to your agent, so your work goes on as before.

Works with Claude Code, Codex and Cursor. Open source (MIT or Apache-2.0).

At a glance

Blocks what must never happen. Quiet about the rest.

Works with

Claude Code, Codex and Cursor, through each agent's own hooks.

Blocks

Reading or sending your keys, tokens and .env files, unknown hosts, curl … | sh, destructive git and file commands, and an agent switching OpenMoat off.

Stays quiet

Installs, pushes and unknown commands go to your agent's own permission prompt, as they did before.

Runs locally

One Rust binary, about 10 ms per check. No AI model decides, and nothing leaves your machine unless you export it.

Get started

Three steps, about a minute.

  1. Install

    brew install crocodile-labs/tap/moat

    Or use the installer, Windows or Cargo command above.

  2. Set it up

    moat init

    It lists the agents it finds and asks Protect Claude Code (~/.claude)? [Y/n] for each one. It backs up every file before it changes it, and moat uninstall puts them back.

  3. Start your agent as usual

    moat status

    Open a new session and work as before. moat status shows each agent's protection, and moat shows today's decisions.

$ moat policy check "cat ~/.ssh/id_rsa"
⛔ deny
   rules : secrets-paths
   reason: secret material: read /Users/you/.ssh/id_rsa
   also  : shell "cat ~/.ssh/id_rsa"

moat policy check gives the verdict for any command, without running it.

How it decides

One local policy, four answers.

Before the agent runs a command, reads or writes a file, opens a web page or calls an MCP tool, OpenMoat checks it against one policy that you control. Written rules decide: the same call gives the same answer every time.

Allow

Normal development work: builds, tests, reading and editing the project, everyday git. It runs, and is recorded.

Defer

Anything the policy has no rule for. Your agent's own permission prompt decides, as it would without OpenMoat.

Ask

Only where the effect outlives the session (a git hook, a login item), or after the session read a secret. You decide, with the reason shown.

Deny

What must never happen: secrets read or sent, unknown hosts, destructive commands, changes to OpenMoat itself. Blocked, with the rule and the reason.

The same policy also configures each agent's operating-system sandbox. Code hidden inside an allowed command, like a test script or a build step, runs inside that sandbox, which keeps it away from your secrets and from files outside the project. What each layer stops is tested in CI and published.

What it protects

Five things an agent should not reach on its own.

Your secrets

SSH keys, cloud credentials, tokens and .env files stay out of reach. With moat secret add, the agent holds a placeholder instead of the real token, and a request that would carry it to the wrong host is blocked.

Your files and history

Recursive deletes of your home directory, force pushes, hard resets and edits to shell startup files are blocked.

Your network

Agents connect only to destinations the policy allows. Cloud metadata services are refused.

OpenMoat itself

The agent can't edit, approve or uninstall OpenMoat through its tools. If the policy or the agent's settings change behind its back, everything is blocked until you review.

A record of every decision

A local audit log that detects tampering, and that your team can export and verify.

Questions

Common questions.

My agent already asks before running commands. Why add this?

The agent's prompt shows you a command, not what it does: a harmless-looking npm test can run code that reads ~/.ssh, and a prompt injection can hide the command in base64 or a variable. In auto-approve modes, CI and background agents there is no prompt at all. OpenMoat reads what the command does, and it blocks what must never happen even when nobody is watching.

Will it slow my agent down?

A check takes about 10 ms. Normal work gets no extra prompts.

Does it send anything anywhere?

No. Decisions are made on your machine, the audit log is a SQLite file in ~/.moat, and credentials are redacted before they are stored. Nothing leaves unless you export it.

Does an AI model decide?

No. Written rules decide: the same call, policy, files and session give the same answer, and moat policy check shows it in advance.

It blocked something I need. What now?

moat allow --last allows that exact command for the session, and --always allows it for good. The usage guide has one command for each case.

How do I turn it off?

moat uninstall takes it out of every agent and puts each settings file back as it was. Your policy and log stay in ~/.moat unless you add --purge.

Limits

What it can't do.

OpenMoat does not replace your agent's prompt or sandbox; it fills the gaps between them. These are the gaps that remain.

  • A deferred call runs if your agent lets it. In auto-approve modes only deny and ask stop a call.
  • Cursor runs some commands outside the sandbox OpenMoat configures (Auto-review approvals, Run Everything mode, the Cursor CLI without --sandbox enabled).
  • Allowed scripts like npm test run whatever they contain. The sandbox bounds them; OpenMoat does not inspect them. On Linux, use moat run --isolate to protect files inside the project.
  • Allowed hosts like api.github.com can still receive data from an allowed command: the proxy checks the host, not what is sent inside HTTPS.
  • Tools no hook exposes are not seen, such as Codex web search and hosted tools.
  • A missing hook binary: if moat is missing or killed, Claude Code and Codex run the call unchecked. moat status reports it.
