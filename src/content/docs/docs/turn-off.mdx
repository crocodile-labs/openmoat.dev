<Aside type="note" title="Read this when">

You need OpenMoat out of the way right now, or you are removing it.

</Aside>

```bash
openmoat uninstall
```

It takes OpenMoat out of every agent it set up and restores each settings file from the backup `openmoat init` made. Restart the agents afterwards.

| You want | Run |
|---|---|
| Remove it from every agent | `openmoat uninstall` |
| Remove it from one agent | `openmoat uninstall --hosts claude-code` |
| Also delete the policy and the audit log | `openmoat uninstall --purge` (not with `--hosts`: the agents left set up would deny every call without it) |
| Set it up again later | `openmoat init` (or `openmoat init --hosts <id>` for one agent) |
| Stop a repository's rules in one project | `openmoat trust --revoke` stops its allow rules; see [Use it in your projects](/docs/your-projects/#stop-using-it) |

It prints one line per file. A file unchanged since `openmoat init` gets its backup back byte for byte, a file `openmoat init` created is deleted, and a file you changed since keeps your changes and loses only OpenMoat's entries. It also stops the lock pinning those files, removes the proxy service if you ran `openmoat proxy install`, and points wrapped MCP servers back at their own commands.

Without `--purge`, your policy and log stay in `~/.moat`, and it says ``· state directory  /Users/you/.moat kept (policy, audit log); `openmoat uninstall --purge` deletes it``. There is no switch for one project: OpenMoat covers every project of a protected agent.

<Aside type="note" title="Run it yourself">

`openmoat uninstall` needs a terminal, and the default policy denies it to agents: a prompt injection cannot switch OpenMoat off.

</Aside>

To remove the binary as well: `brew uninstall openmoat`, or delete `~/.cargo/bin/openmoat` and `~/.cargo/bin/moat` if you used the installer or `cargo install`.
