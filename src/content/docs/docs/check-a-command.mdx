<Aside type="note" title="Read this when">

You want to know whether a command will be blocked, or why it was.

</Aside>

```bash
openmoat policy check "git push origin main"
```

```text
→ defer
   rules : default
   reason: no rule matched shell "git push origin main"
```

`openmoat policy check` runs nothing. It parses the command the way the hook does and prints the answer, the rules that decided it and the reason.

## More examples

```bash
openmoat policy check "cat ~/.ssh/id_rsa"                      # deny: secrets-paths
openmoat policy check "git config core.hooksPath .h"           # ask: git-internals
openmoat policy check "https://docs.rs/serde" --kind fetch     # a web fetch, not a shell command
openmoat policy check "~/.aws/credentials" --kind fs-read      # a file read by a file tool
```

The first line of the output is the answer: `✔ allow`, `→ defer`, `❓ ask` or `⛔ deny`.

## In another project

```bash
openmoat policy check "npm run migrate" --cwd ~/work/app
```

It decides as if the command ran in `~/work/app`: `${project}` is that repository's root, and its `.moat/policy.yaml`, if it has one, applies as in the hook (rules shown as `repo:<id>`). `--project <dir>` sets the project root directly. With `--policy <file>`, only that file decides: no `openmoat allow` rules, packs or repository policy. See [Use it in your projects](/docs/your-projects/#check-a-project).

## A few examples at once

```bash
openmoat demo
```

It decides a fixed list of example agent calls (everyday work, a private key read, a key sent out, the same read base64-encoded, a misspelled package, a plain download, switching OpenMoat off) with your installed policy, or the default one, and prints each command with its verdict, rule and reason. It uses the same engine as `openmoat policy check`; nothing runs, and no hook, setting or file is changed.

## Use it in scripts

The exit code is the answer:

| Exit code | Answer |
|---|---|
| `0` | allow or defer |
| `2` | deny |
| `3` | ask |
| `64` | a usage or configuration error |
