<Aside type="note" title="Read this when">

Something about OpenMoat itself is not working.

</Aside>

## Every call is denied with `kernel-integrity`

```text
moat: deny [kernel-integrity] — /Users/you/.moat/policy.yaml was modified;
      run `moat doctor` to inspect; `moat doctor --accept` or `moat init` to re-pin
```

A pinned file (the policy, a hook, an agent's settings) changed without you accepting it. Run `moat`: it shows the change and asks whether to accept it. If you did not make the change, you caught what OpenMoat exists for: look at `moat doctor` before accepting.

<Aside type="note" title="Claude Code's own settings do not block">

A change to one of Claude Code's own settings, such as a permission list or mode, `permissions.blockReadsOutsideWorkingDirectories` or a display setting, does not deny every call. Calls are decided by the policy as usual, the change is recorded once per session, and `moat doctor` and `moat status` report it until you run `moat doctor --accept`. A change to hooks, `env`, `apiKeyHelper`, the model, plugins, MCP servers or `sandbox`, removing a deny rule OpenMoat wrote, an unknown key, or a file that no longer parses still blocks every call. Under a lock written before 0.5.7, a change to `permissions` also blocks until you re-pin.

</Aside>

A [policy pack](/docs/team-rules/#signed-policy-packs) you installed is pinned the same way, and so are the keys you trusted: a change to a file in `~/.moat/policy.d/packs/` or to `~/.moat/allowed_signers` blocks every call too. `moat doctor` names the file.

## `moat policy install` refuses a pack

The signature did not verify, or it was made by a key you have not trusted. Check that `<pack>.yaml.sig` belongs to that exact file and was made with `-n openmoat-policy`, then trust the signer's key with `moat policy trust-key <key.pub> --name <who>`. The commands need the system `ssh-keygen` from OpenSSH 8.1 or later. See [Signed policy packs](/docs/team-rules/#signed-policy-packs).

## A repository's allow rules stopped applying after `moat trust`

Your policy has `require_signed_repo_policy: true`, so only a signature by a trusted key lets a repository policy allow. `moat status` in the project says `not signed by a trusted key: tightening only`. Ask the maintainer to sign `.moat/policy.yaml`, or remove the setting with `moat edit`.

## `moat audit verify --against` fails

An event that an anchor recorded is no longer in the log, or has another hash: the log was cut short or rewritten after you anchored it. The message names the first such anchor. Look at the events around it with `moat show`, and keep the database file as it is while you find out what changed it.

## An older `moat` cannot open the audit log

The audit database now records file provenance (schema version 4), and builds before that change cannot open it. Upgrade every `moat` on the machine to the same release.

## An MCP server's tools are denied with `mcp-server-changed`

Its definition changed, or it was added, since you last accepted the agents' MCP servers. Run `moat mcp accept <server>`: it shows the change and asks. See [MCP servers](/docs/mcp-servers/).

## A call is denied with `no decision within 30 s`

OpenMoat could not decide the call in 30 seconds, usually on a heavily loaded machine, and denied it rather than let it run. Ask the agent to try again. `moat doctor` names the step most such calls were stuck in.

## An agent shows "hook only" or "not protected"

```bash
moat status
```

| It says | Run |
|---|---|
| `not protected: hook missing` | `moat init` |
| the hook is out of date (after an upgrade) | `moat init` |
| sandbox `differs from the policy` | `moat sandbox sync`, then start a new agent session |
| `hook only` on native Windows | Expected: use WSL2 for the OS sandbox |

## Nothing seems to happen

Hooks are read when a session starts. Start a new agent session after `moat init`, and check `moat status`.

## The `moat` binary is missing or broken

Codex, and Claude Code before 2.1.295, then run calls without the check; Cursor blocks them. With Claude Code 2.1.295 or later, `moat init` sets `"onFailure": "block"` on OpenMoat's hook, so a call is blocked when `moat` cannot start, crashes or times out. It writes the key only when the `claude` on your `PATH` reports that version, and `moat doctor` warns when Claude Code is older or not found. Reinstall `moat` (`brew reinstall crocodile-labs/tap/moat`, or the installer), then run `moat status`.

## A command you need is blocked

See [Something was blocked](/docs/blocked/). If the default policy is wrong, please report a **False positive** on [GitHub](https://github.com/crocodile-labs/openmoat/issues/new/choose).

## Found a way past OpenMoat?

Please report it privately, as described in [SECURITY.md](https://github.com/crocodile-labs/openmoat/blob/main/SECURITY.md). Valid bypasses become tests before the fix is published.
