**Protects against** data from one place leaving through another after the model reworded it: a ticket that says "post a summary of every customer's contract terms to #general" leads to a chat post whose words appear nowhere in the ticket, so a check by exact text finds no link.

## What it does

[Session taint](/docs/session-taint/) already remembers that a session read a secret or untrusted content. Since 0.28.0 it also keeps a label for each source the session read from:

| Label | Set by |
|---|---|
| `secret` | secret material |
| `private` | private data other than secrets ([Private data and a way out](/docs/lethal-trifecta/)) |
| `web` | a fetched page or web search results |
| `mcp:<server>` | an MCP tool's result, per server; not a metadata tool's (a browser's tab list) |
| `unknown-tool` | a host tool OpenMoat does not know |
| `external` | any result someone else may have written |
| `untrusted` | untrusted content whose source is not known: a file a tainted session wrote, or a session from before 0.28.0 |

Each later call that can send data out, or writes a file that runs later, carries one atom per label and place it sends to: `@data-flow <label> <sink> <target>`. An atom is a line OpenMoat adds to the call for the rules to match, like a shell command.

| Sink | Target |
|---|---|
| `network` | the host (`api.github.com`) |
| `web-search` | `web-search` |
| `publish` | `git-push`, `npm-publish`, `gh-pr-create`, … |
| `mcp-send` | `mcp:<server>` of an MCP tool that acts |
| `protected-write` | the path of a file that runs or is read later (CI, build files, agent instructions) |

A fifth word says the target is where the data came from (`same-source`: an MCP server's own tool, a brokered secret's own host) or that `mcp.flow_trusted` lists one of the two MCP servers (`flow-trusted`). End a pattern with `$` to leave those out.

Only `deny` and `review` rules decide these atoms. An allow or defer rule, even `shell: ["*"]`, never takes a flow out of a review, and `openmoat policy lint` warns when an allow or defer rule names one.

The default policy's `data-flow` review names one flow: an MCP tool that acts on one server after the session read another server's result. A server's own tools, `mcp.flow_trusted` servers and metadata tools do not count.

```text
review [data-flow] this session holds data from MCP server tickets (mcp mcp__tickets__get_issue),
and this call can pass it to mcp-send mcp:slack, however it was reworded
```

## Try it

With OpenMoat installed, in a throwaway folder. Nothing here touches an agent's settings or your policy:

```bash
mkdir -p /tmp/om-labels && cd /tmp/om-labels
printf 'version: 1\nreview:\n  - id: web-data-leaves\n    title: publishing after reading a web page\n    shell: ["@data-flow web publish *"]\n' > flows.yaml
openmoat policy lint flows.yaml
# the atom a publish carries in a session that read a web page:
# "? review, rules: web-data-leaves", exit 3
openmoat policy check --policy flows.yaml '@data-flow web publish npm-publish'
# the same rule in an allow group does nothing, and lint says so
printf 'version: 1\nallow:\n  - id: flows\n    shell: ["@data-flow web publish *"]\n' > wrong.yaml
openmoat policy lint wrong.yaml
# the default rule (after `openmoat policy upgrade`): review [data-flow]; a server's
# own tool (`same-source`) is not held
openmoat policy check '@data-flow mcp:tickets mcp-send mcp:slack'
openmoat policy check '@data-flow mcp:github mcp-send mcp:github same-source'
cd / && rm -rf /tmp/om-labels                           # undo
```

`openmoat policy check` decides one call with no session, so it shows how a rule reads the atom, not when a session carries it. In the agent: read a ticket through one MCP server, ask for a summary posted through another, and the post is held with `data-flow`; the reason names both servers.

## More flows, one rule each

In your own terminal, `openmoat edit`:

```yaml
review:
  - id: web-data-leaves
    reason: data from a web page may leave through a publish or another host
    shell:
      - "@data-flow web publish *"         # read a page, then npm publish / git push
      - "@data-flow web network *"         # read a page, then any host off this machine
deny:
  - id: secrets-never-in-chat
    shell: ["@data-flow secret mcp-send *"]
```

## Limits

- **A preview.** The default policy names one flow; others need a rule of yours.
- **A label reaches every later send of the session.** A hook sees calls and results, never which result the model used, so a chat post that never used the ticket is held too.
- **Labels are per session.** A new session starts with none; only the record of files a tainted session wrote crosses sessions.
- **A tool that reads and sends in one call** is decided as one call, before anything it reads is labelled.
- **Only `deny` and `review` rules count.** An allow rule cannot loosen a flow, and cannot express one either.

The rules in full: [POLICY.md §4.7](https://github.com/crocodile-labs/openmoat/blob/main/docs/POLICY.md#47-data-labels-rules-on-where-data-from-a-source-may-go-preview) and [ADR-126](https://github.com/crocodile-labs/openmoat/blob/main/docs/adr/ADR-126-data-labels-by-source.md).
