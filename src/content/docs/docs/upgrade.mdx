import { Aside, Steps, TabItem, Tabs } from '@astrojs/starlight/components';

<Aside type="note" title="Read this when">

A new OpenMoat release is out, or `moat` says "policy update available".

</Aside>

<Steps>

1. **Upgrade the binary**

   <Tabs>
   <TabItem label="Homebrew">

   ```bash
   brew update && brew upgrade moat
   ```

   </TabItem>
   <TabItem label="Installer">

   Run the installer of the new release again, as in the [Quick start](/docs/quickstart/).

   </TabItem>
   <TabItem label="Cargo">

   ```bash
   cargo install openmoat --locked --force
   ```

   </TabItem>
   </Tabs>

   Hooks keep working after an upgrade in the same place. `moat doctor` confirms it.

2. **Take the new default rules, if you want them**

   Your policy is kept as it is, so a rule the new default gained is offered, not forced. `moat` says "policy update available: N changes" and offers to show them.

   ```bash
   moat policy upgrade --dry-run   # what the new default adds, as a diff; changes nothing
   moat policy upgrade             # shows the diff, asks, keeps a backup and re-pins
   moat policy upgrade --undo      # put the previous policy back
   ```

   Lines you changed are never touched.

</Steps>

<Aside type="note" title="Upgrading to 0.5.7">

- **Run `moat init` once.** Claude Code's hook shows as out of date until you do: it now also receives MCP resource reads, worktree entries and skills, and with Claude Code 2.1.295 or later it gets `"onFailure": "block"`, so a call is blocked when `moat` cannot start, crashes or times out. `moat init` also pins your agents' MCP servers ([MCP servers](/docs/mcp-servers/)).
- **Run `moat policy upgrade`** to get `token-egress` and `placeholder-egress` ([tokens sent to the wrong host](/docs/keep-tokens-safe/#tokens-sent-to-the-wrong-host)), the new `runs-later` files, and the deny of `moat mcp accept`, `wrap` and `unwrap` to agents.

</Aside>

<Aside type="note" title="Upgrading to 0.7.0">

- **Run `moat policy upgrade`** to get the new denies: more credential files (`~/.pgpass`, `~/.my.cnf`, `~/.vault-token`, `~/.authinfo` and others), more secret variables (`DATABASE_URL` and other connection strings, `*_PASSWORD`-style names), and commands that print a stored secret (`vault kv get`, `pass show`, `kubectl config view --raw`).
- **Nothing to do for the rest.** The other checks apply as soon as the new binary runs: `tar` and `su` options that run a program, bash network redirections (`/dev/tcp/…`), MCP server pins under `CLAUDE_CONFIG_DIR`, and faster checks in long sessions.
- **Switching models in Claude Code** no longer stops every call until `moat doctor --accept`.
- **Reporting a bug?** `moat doctor --bundle report.json` writes one local file to attach; it keeps no commands, paths or secrets.

</Aside>

Every release and what changed in it: [Releases](https://github.com/crocodile-labs/openmoat/releases).
