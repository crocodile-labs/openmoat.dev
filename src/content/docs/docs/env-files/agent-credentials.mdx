<Aside type="note" title="Read this when">

A read of an agent's `auth.json` or token folder was denied with rule `agent-credentials`, or you want to know what keeps one agent from reading another's login.

</Aside>

**Protects against** an agent reading or overwriting the login, provider keys and OAuth tokens that Claude Code, Codex, GitHub Copilot CLI, pi, Gemini CLI, OpenCode, Hermes Agent, OpenClaw and the Continue CLI keep on your machine, its own included, and then sending them out.

## What it does

The default rule `agent-credentials` denies the agent's own tools reading or writing those files: a shell command naming them, a file tool, an MCP argument. Examples are OpenCode's `~/.local/share/opencode/auth.json`, Hermes Agent's `auth.json` and `mcp-tokens/`, and Codex's `auth.json`. It also covers an agent directory you moved to another place.

Commands that print a stored agent token are covered too: `pi auth print-api-key`, `pi auth print-bearer-token`, `opencode auth export` and `secret-tool lookup` are denied, and `claude setup-token` asks (`agent-token`).

| Command | Verdict | Rule |
|---|---|---|
| `cat ~/.codex/auth.json`, `cat ~/.local/share/opencode/auth.json` | deny | `agent-credentials` |
| `claude setup-token` | ask | `agent-token` |

The rule is in the hook only. Under `openmoat run`, and in the agents' own sandboxes, each agent still reads its own login, which it needs to work.

## Example

```bash
openmoat policy check "cat ~/.codex/auth.json"
```

The first line of the output is `⛔ deny`, and the rule is `agent-credentials`.

Copying the whole folder that holds such a file is one read of the folder, not of the file. That asks, with rule `protected-contents`: see [Folders that hold denied files](/docs/env-files/protected-contents/).

## Commands

| Command | What it does | Example |
|---|---|---|
| `openmoat policy upgrade` | Takes the `agent-credentials` rule into a policy written before 0.11.0 | `openmoat policy upgrade` |
| `openmoat policy check "<command>"` | Shows the verdict and rule; nothing runs | `openmoat policy check "cat ~/.local/share/opencode/auth.json"` |
| `openmoat edit` | The only way to change a deny rule | `openmoat edit` |

## Limits

- **Hook only.** A sandbox leaves these files readable, since the agent reads its own login there. A program a sandboxed command runs, or a script that builds the path at run time, can still read them. Where no OS sandbox holds the command, a script the session wrote asks before it runs ([Code the agent wrote](/docs/session-written-code/)).
- **A folder copy, once approved, holds the files.** `cp -r ~/.codex x` asks; if you approve it, the copy contains the login.

The full list: [Limits](/docs/limits/) and [THREAT_MODEL.md §5](https://github.com/crocodile-labs/openmoat/blob/main/docs/THREAT_MODEL.md#5-known-limitations).
