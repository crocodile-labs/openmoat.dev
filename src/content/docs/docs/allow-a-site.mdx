A shell command like curl is denied with `default.net`.

**Protects against** a command sending your code or data to a host a prompt injection named.

## What it does

Outbound network access from shell commands that can send data is denied by default: an unknown host is where a prompt injection would send your data. The default policy lists the hosts development needs (GitHub, npm, crates.io, PyPI, the Go proxy). A command that can send anything to another host is denied:

```text
moat: deny [default.net] — no rule matched net docs.rs
```

A plain download is not: a `curl` or `wget` that provably sends nothing but its URL and reads no configuration file of its own (`curl -q https://docs.rs/serde`, `curl -q -sS https://example.com/f.txt -o f.txt`, `wget --no-config --no-netrc …`) is decided like a web fetch, so it goes to your agent's own prompt. A body, form, upload, header, another method, credentials or following redirects (`curl -L`) keeps it denied, and so does a `curl` without `-q` first, which reads `~/.curlrc`.

| Command | Verdict | Rule |
|---|---|---|
| `curl -q https://docs.rs/serde`, `curl -q -sS https://example.com/f.txt -o f.txt` | defer | `default.fetch`: a download that sends nothing, decided like a web fetch |
| `curl https://docs.rs/serde` | deny | `default.net`: without `-q` first, curl reads `~/.curlrc`, which may add a body |
| `curl -d @notes.txt https://example.com` | deny | `default.net`: sends data to a host the policy does not list |
| `curl http://169.254.169.254/` | deny | `cloud-metadata`, whatever the policy allows |

## Example

<Steps>

1. **Allow the host, in your own terminal**

   ```bash
   openmoat allow --site docs.rs
   ```

   ```text
   ✔ added to /Users/you/.moat/policy.d/approved.yaml:
       - id: approved-2
         reason: approved with `openmoat allow --site` on 2026-10-15 09:12:04 UTC
         net:
         - docs.rs
     undo: openmoat allow --remove approved-2
   ✔ lock re-pinned (6 files)
   ```

   It also updates the OS sandboxes of the agents that have one (Claude Code, Codex, Cursor), so sandboxed commands can reach the host too.

2. **Start a new agent session, or ask the agent to try again**

   Fetch tools see the change at once; sandboxed shell commands after a new session.

</Steps>

## What changes

| The agent uses | Before | After |
|---|---|---|
| A web fetch tool (Claude Code `WebFetch`) on `docs.rs` | your agent's prompt | **allowed**, no prompt |
| `curl -q https://docs.rs/serde` (sends nothing) | your agent's prompt | not denied |
| `curl https://docs.rs/serde`, `curl -L https://docs.rs/` or `curl -d @notes.txt https://docs.rs/` | denied | not denied: your agent's prompt, like any command the policy does not list |
| `curl -q https://www.docs.rs/` | your agent's prompt | unchanged: another host |

## Good to know

- **One exact host.** Wildcards, URLs and ports are refused here; write those with `openmoat edit` ([Change the rules](/docs/change-the-rules/)).
- **Ports 443 and 80.** Through `openmoat proxy` and `openmoat run`, the host is reached on those two ports only. For another port, add `host:port` next to the host with `openmoat edit` ([a port other than 443 or 80](/docs/troubleshooting/#a-connection-to-a-port-other-than-443-or-80-is-refused)).
- **Already allowed:** `github.com`, `api.github.com`, `registry.npmjs.org`, `crates.io`, `static.crates.io`, `index.crates.io`, `proxy.golang.org`, `pypi.org`, `files.pythonhosted.org`.

## Undo it

```bash
openmoat allow --remove approved-2
```

## Commands

| Command | Example |
|---|---|
| `openmoat allow --site <host>`: network access to one exact host. Terminal only | `openmoat allow --site docs.rs` |
| `openmoat allow --remove <id>`: take it back | `openmoat allow --remove approved-2` |
| `openmoat allowed`: what you allowed, with the command that undoes each | `openmoat allowed` |
| `openmoat policy check "<url>" --kind fetch`: a fetch tool's verdict | `openmoat policy check "https://docs.rs/serde" --kind fetch` |
| `openmoat policy check "<command>"`: a shell command's | `openmoat policy check "curl -q https://docs.rs/serde"` |

## Settings

A pattern, several hosts or a port, with `openmoat edit`:

```yaml
allow:
  - id: company-registry
    net: ["npm.internal.example.com", "pypi.internal.example.com"]
  - id: example-8443
    reason: the staging API listens on 8443
    net: ["example.com", "example.com:8443"]
```

`net` patterns also match fetches; a `fetch` pattern matches only fetch tools and `curl -q`-style downloads. `defaults: net: deny` is what denies unlisted hosts.

## Limits

- **The host can receive whatever the agent sends it.** OpenMoat checks the host, not the data inside HTTPS.
- **The hook cannot see a host name that resolves to an internal address**; under `openmoat run` and the agents' sandboxes, link-local and metadata addresses are still refused after DNS, and `openmoat proxy` also refuses private ones the policy does not name.
- **For a hook-only agent, an allowed command connects to any port** of an allowed host: ports count only in the proxy.

More in [Limits](/docs/limits/).
