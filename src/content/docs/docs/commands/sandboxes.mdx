Commands marked **terminal** must be run by a person in a terminal of their own ([Commands](/docs/commands/)).

| Command | What it does | Example |
|---|---|---|
| `openmoat sandbox show` | The agents' sandbox settings the policy compiles to, and every place they are stricter or wider; writes nothing | `openmoat sandbox show` |
| `openmoat sandbox sync` | Write them for the agents whose hook is installed, and re-pin. **Terminal** | `openmoat sandbox sync` |
| `openmoat run [--isolate\|--no-isolate] [--write <path>]… [--env NAME]… [--netns auto\|require] [--no-snapshot] [--verbose] -- <agent> [args]` | Run an agent and everything it starts in a sandbox made from the policy, network only through OpenMoat's proxy (macOS 13 or later, Linux; on native Windows a preview that holds writes outside the project and the agent's processes, and after `openmoat agent-account setup` also reads and the network, [openmoat run on Windows](/docs/sandboxes/windows/)). On Linux the Isolated tier (bubblewrap) by default where it works; `--isolate`: refuse without it; `--no-isolate`: the Lightweight tier, recorded; `--env NAME`: let one more inherited variable through under `require.run: full-boundary`; `--netns=require`: refuse where the agent cannot get a network namespace; `--no-snapshot`: take no snapshot of the project ([Undo an agent's changes](/docs/snapshots/)) | `openmoat run --write ~/.claude --write ~/.claude.json -- claude` |
| `openmoat run --vm -- <agent>` | The microVM tier, a design (from 0.28.0): refuses on every system (exit 64) and starts nothing, naming the VM monitor this system would use, the policy's `sandbox.vm` image and the tier's score ([OS sandboxes and run](/docs/sandboxes/#the-microvm-tier-designed-not-built)) | `openmoat run --vm -- claude` |
| `openmoat agent-account setup` | Windows: make a local account for agents, grant it read on your profile and install network filters for it, so `openmoat run` starts agents as it and Windows refuses their denied reads and every connection but the proxy. From an administrator terminal, once. **Terminal** (from 0.28.0, preview, [openmoat run on Windows](/docs/sandboxes/windows/#run-the-agent-as-its-own-account-preview)) | `openmoat agent-account setup` |
| `openmoat agent-account status` | Compare the system with what setup recorded; exit 1 when it differs | `openmoat agent-account status` |
| `openmoat agent-account remove` | Undo setup: the filters, every access-list entry, the account and its profile. From an administrator terminal. **Terminal** | `openmoat agent-account remove` |
| `openmoat run --print-boundary [--format json] -- <agent>` | Print the sandbox boundary this run would start with and start nothing (from 0.21.0): the tier asked for and the one that starts, each downgrade with why, the network mode, the Landlock ABI, whether tool commands get the relay token, and each restriction's available / configured / applied / tested. Every run writes the same record to the audit log (`run-boundary`) ([The boundary record](/docs/sandboxes/boundary-record/)) | `openmoat run --print-boundary -- claude` |
| `openmoat run --listen <port> … -- <agent>` | Let the agent serve one TCP port (1024 or above) on loopback alone, such as OpenClaw's Gateway: it may bind no other port or address and still connects only to the proxy. Linux with a network namespace only: the port is forwarded from this machine's `127.0.0.1` into the sandbox's network. Refused on Linux without a network namespace, on macOS (Seatbelt's filter lets a bind to every address on the port through too) and on Windows (from 0.27.0, [Confine agents by default](/docs/sandboxes/confine/#openclaw-under-openmoat-run---listen)) | `openmoat run --listen 18789 --write ~/.openclaw -- openclaw gateway` |
| `openmoat confine <agent>… \| --all` | Make typing a hook-only agent's name start it in `openmoat run`'s sandbox: writes a shim in `~/.moat/bin` and, once, the lines that put that folder first on `PATH` in your shell's start-up file (after a backup), shows the protection score it gains, and re-pins. Exit 64 when nothing could be done for the agents named. **Terminal** (from 0.27.0, [Confine agents by default](/docs/sandboxes/confine/)) | `openmoat confine gemini-cli` |
| `openmoat confine --off <agent>… \| --all` | Start those agents as before: deletes the shims still as written, and the `PATH` lines with the last. **Terminal** | `openmoat confine --off --all` |
| `openmoat snapshot [--list [--format json] \| --prune]` | Take a snapshot of the project's files, list this project's snapshots and what each left out, or remove those past the retention. **Terminal** | `openmoat snapshot --list` |
| `openmoat restore [<id>] [--patch] [-- <path>…]` | Put the project's files back as a snapshot holds them (by default the newest one taken before an agent started): takes an undo snapshot, shows each change and asks. **Terminal** | `openmoat restore` |
| `openmoat proxy [--listen 127.0.0.1:<port>]` | The egress proxy, in this terminal; it serves only requests with a session credential (Claude Code's sessions get one from their `SessionStart` hook) unless `sandbox.proxy_serve_without_credential` is set; an allowed host is reached on ports 443 and 80 unless a rule names `host:port` | `openmoat proxy` |
| `openmoat proxy ca init` | Make the CA `openmoat run`'s proxy decrypts HTTPS with, for the hosts of `tls: terminate` secrets only; asks, then pins it. **Terminal** | `openmoat proxy ca init` |
| `openmoat proxy install` · `uninstall` | Run it as a user service (launchd, systemd), or remove it; not on Windows yet. **Terminal** | `openmoat proxy install` |
| `openmoat proxy status [--format json]` | `not installed`, `stopped`, `running`, `drift-blocked` or `crashlooping` | `openmoat proxy status` |

See [OS sandboxes and openmoat run](/docs/sandboxes/), [Egress proxy](/docs/egress-proxy/) and [The proxy serves agent sessions only](/docs/egress-proxy/sessions/).
