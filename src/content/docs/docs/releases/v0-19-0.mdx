Released 2026-11-09. [GitHub release v0.19.0](https://github.com/crocodile-labs/openmoat/releases/tag/v0.19.0).

<Aside type="caution" title="Upgrading">

- **Run `openmoat policy upgrade`** in your own terminal for the new and changed default rules.
- **Then run `openmoat init` once.** Hooks now carry OpenMoat's state directory in their command; hooks of the old form show as out of date until then.
- **Inside `openmoat run`, commands no longer read the shared temp directories.** A tool that reads a fixed path in `/tmp` written by another program now fails there.
- **Library crates:** a break, hence 0.19.0. See the **Breaking** entries under Changed.

Every step after an upgrade: [Upgrade](/docs/upgrade/).

</Aside>

## Security
- `openmoat doctor` checks the mode and owner of the state directory and each file in it that decides or records a call (lock, policy, approvals, trust and host records, audit log, keys): a file other users may write, or one another user owns, is a problem with the `chmod` or `chown` that fixes it, one they may read or a symbolic link is a warning, and `--verbose` lists every file's mode and owner. Not checked on Windows (ADR-071) ([#772](https://github.com/crocodile-labs/openmoat/pull/772)).
- The lock records the SHA-256 and release of the binary the hooks run, and `openmoat guard` compares the file it runs from with it (hashed once per change of the file, cached beside the lock): other bytes under the same release deny every call until `openmoat init`, and `openmoat status` and `openmoat doctor` show it; an upgrade to another release keeps working and is only reported until `openmoat init` records it (ADR-071) ([#772](https://github.com/crocodile-labs/openmoat/pull/772)).
- `openmoat init` writes the state directory into every hook it installs (`guard --host <id> --home <dir>`, pinned by the lock with the hook file), and `openmoat guard` decides with that directory whatever the agent's environment says: a `MOAT_HOME` in the hook's environment that names another directory makes it deny the call. Before, an agent that built its hooks' environment from a file or setting OpenMoat does not guard could point the guard at another policy and lock. Hooks written by earlier releases still work and show as out of date in `openmoat status` and `openmoat doctor` until you run `openmoat init` (ADR-071) ([#772](https://github.com/crocodile-labs/openmoat/pull/772)).
- A shell command that creates or replaces a project file an agent reads as its hook settings (`.codex/config.toml`, `opencode.json`, `.pi/settings.json`, by a redirect, `tee`, `cp`, `mv` or `sed -i`) is denied (`project-settings`) where that agent would load it and OpenMoat is set up for it, because what it leaves cannot be known before it runs. Reading those files, removing them, moving them away, and same-named files elsewhere keep their verdict; changes through the agent's file tools are judged by their content as before ([#773](https://github.com/crocodile-labs/openmoat/pull/773)).
- Under `openmoat run`, tool commands of Claude Code, OpenCode, goose, Hermes Agent, OpenClaw, the Continue CLI and pi no longer receive the run's relay token, and a command cannot read it from the agent that started it (macOS: the sandbox denies `kern.procargs*`; Linux: no grant covers `/proc`, and a wrapped command gets a Landlock layer of its own). Codex, Cursor, GitHub Copilot CLI, Gemini CLI, the Cline CLI and the Antigravity CLI start tool commands in a way OpenMoat cannot yet tell from their hooks, so theirs still do. `openmoat doctor` names both groups and `openmoat bench --report` tries the attack (ADR-075) ([#774](https://github.com/crocodile-labs/openmoat/pull/774)).
- `echo … | base64 <-d | sh ; true` was held for review where the same line without `; true` was denied: a decoder's dash-word after a redirection now counts as its flag ([#775](https://github.com/crocodile-labs/openmoat/pull/775)).
- `openmoat run` no longer lets commands read the shared temp directories: `/tmp` and macOS's temp folder are left out of its read roots (the run keeps its own temp directory; macOS keeps its per-user caches), which also closes Kerberos ticket caches in `/tmp` on Linux without a network namespace (ADR-018) ([#775](https://github.com/crocodile-labs/openmoat/pull/775)).

## Added
- Antigravity CLI (`agy`) support: `openmoat init` writes a named `openmoat` entry with one `PreToolUse` hook to `~/.gemini/config/hooks.json`, shared with the Antigravity app and IDE. Every documented tool is mapped by what it does; a review is sent as `force_ask` so a saved "Always Allow" cannot answer it, and a saved `toolPermission: always-proceed` turns one into a deny. The default policy keeps the agent from changing its hook, settings, MCP and plugin files and from reading its MCP OAuth tokens. Built from the official documentation (no version stated) and not yet checked against a running `agy`: what the host does when the hook fails is not documented, so treat a failing hook as letting the call run ([#774](https://github.com/crocodile-labs/openmoat/pull/774)).

## Changed
- **Breaking** `openmoat-hosts`: `HookFile::entry`, `HookFile::upsert`, `HookFile::state`, `yaml_hooks::upsert`, `ConsentFile::upsert` and `ConsentFile::holds` take a `&GuardCommand` (the binary and the state directory the hook names) instead of the binary as `&str`, and `OwnedFile::text` takes the state directory as a second argument; the crate exports `GuardCommand`, `HOME_FLAG`, `encode_home` and `decode_home` ([#772](https://github.com/crocodile-labs/openmoat/pull/772)).
- The row that ties an agent session to an `openmoat run` now says that the session's rows come through the run's relay, which any program in the run's sandbox can use, so they show what was asked from inside the run, not that the agent asked it. THREAT_MODEL, LIMITS and ADR-071 say why the relay token cannot be bound to the agent's hook process on any OS today, and what the run still refuses (ADR-071) ([#772](https://github.com/crocodile-labs/openmoat/pull/772)).
- **Breaking** `openmoat-hosts`: `Host` gains `AntigravityCli`, so an exhaustive `match` on `Host` needs the new arm; `HookFile` gains `section`, `section_switch` and `turned_off`, and `Unseen` gains `file` ([#774](https://github.com/crocodile-labs/openmoat/pull/774)).
- The end-to-end tests run an MCP server that tries to read a planted secret by a relative path, an absolute path and a symbolic link out of its folder and to write outside the project: `openmoat mcp proxy --sandbox` is shown to stop each by the files on disk, and the same calls reach the files without it, as `docs/LIMITS.md` now says ([#775](https://github.com/crocodile-labs/openmoat/pull/775)).

## Fixed
- `openmoat run` on Linux no longer refuses to start when `TMPDIR` is so long that its network namespace's socket could not be bound; the proof report's OS rows now run on Linux with bubblewrap (ADR-065) ([#775](https://github.com/crocodile-labs/openmoat/pull/775)).
