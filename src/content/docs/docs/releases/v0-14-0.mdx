Released 2026-11-05. [GitHub release v0.14.0](https://github.com/crocodile-labs/openmoat/releases/tag/v0.14.0).

<Aside type="caution" title="Upgrading">

- **`ask` is now called `review`.** Your policy keeps working as it is, and `openmoat policy lint` warns until you rename it. Run `openmoat policy upgrade` in your own terminal: it shows the rename in its diff and asks before writing. The same calls still need your approval, and every agent still receives its own word for it.
- **`openmoat policy upgrade` also adds `card-egress`,** the new default rule that denies a payment card number sent off the machine.
- **JSON output says `"review"`,** and the keys `asked` and `top_asks` are now `reviewed` and `top_reviews`. Update scripts that read them.
- **The audit database moves to schema version 8.** Rows written before keep verifying and read as `review`. An older OpenMoat refuses to open the upgraded database, so don't downgrade without restoring a backup.
- **New agents:** run `openmoat init` once to protect goose or the Cline CLI.
- **Library crates:** `Verdict::Ask` is `Verdict::Review` (and the items named after it), and `Host` gains `Cline` and `Goose`. See the [changelog](https://github.com/crocodile-labs/openmoat/blob/main/CHANGELOG.md).

Every step after an upgrade: [Upgrade](/docs/upgrade/). The rename step by step: [Upgrading from ask to review](/docs/upgrade/ask-to-review/).

</Aside>

## Security

- **Card numbers stay on the machine.** A payment card number in what a call sends (a URL a fetch, network or MCP tool opens, a web search, or a command that connects to a host such as `curl -d` or a pipe into `curl`) is denied (`card-egress`). A number counts only if it has a card brand's prefix and length and passes the Luhn check. Sends to this machine and the test numbers payment processors publish are left out; file contents and encoded data are not read. Ten or more distinct mail addresses in one send become the atom `@pii-egress emails <host>`, which no default rule names; a rule for `@pii-egress emails *` denies them or holds them for review ([Card numbers sent out](/docs/env-files/card-numbers/)) ([#719](https://github.com/crocodile-labs/openmoat/pull/719)).

## Added

- **Check a pull request before merge.** `openmoat policy check-diff --base main` decides every file a change adds, edits, deletes or renames with the policy's own rules: CI workflows, git hooks, build and package files and agent settings are reported for `review`, what the policy denies an agent (`.claude/settings.json`, `.env`, `.moat/`) as `deny`, and added lines holding a known token format are reported too. The policy is read as the base branch has it, so a change cannot loosen its own check. A GitHub Action (`action.yml` in the repository) runs it on pull requests with a checked release ([Check a pull request](/docs/check-a-pull-request/)) ([#717](https://github.com/crocodile-labs/openmoat/pull/717)).
- **Compliance evidence from the audit log.** `openmoat audit evidence` reports, per control of the OWASP Top 10 for LLM Applications 2025, SOC 2 (CC6 to CC8) and ISO/IEC 27001:2022 Annex A, which rules fired, decisions by verdict, redacted sample events, the hash chain, the policy hash and each agent's protection level. It is evidence, not a certification ([Compliance evidence](/docs/compliance-evidence/)) ([#718](https://github.com/crocodile-labs/openmoat/pull/718)).
- **goose is supported.** `openmoat init` writes OpenMoat's goose plugin with `on_failure: block`, so a hook that fails blocks the call. goose cannot prompt, so a review is a block you approve with `openmoat allow --last` ([goose](/docs/agents/goose/)) ([#715](https://github.com/crocodile-labs/openmoat/pull/715)).
- **The Cline CLI is supported.** `openmoat init --hosts cline` writes OpenMoat's hook script, which blocks the call itself when `openmoat` is missing or does not answer. The Cline VS Code extension, `--yolo` runs and native Windows are not covered ([Cline CLI](/docs/agents/cline/)) ([#716](https://github.com/crocodile-labs/openmoat/pull/716)).

## Changed

- **The `ask` verdict is now `review`** everywhere OpenMoat shows or stores it: the policy's `review:` list, `openmoat status`, `doctor`, `show`, `report`, `audit` and MoatBench output, JSON, the reason line (`moat: review [rule]`), the SDKs and the docs. Exit code 3 still means an unresolved review. A policy with both `ask:` and `review:` is refused with a message saying which rules to move ([#721](https://github.com/crocodile-labs/openmoat/pull/721)).
