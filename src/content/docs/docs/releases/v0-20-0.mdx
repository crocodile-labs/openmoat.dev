<Aside type="caution" title="Upgrading">

- **Run `openmoat policy upgrade`** in your own terminal for the new and changed default rules: `kernel-self` now also covers `~/.moat/delivery/`, `~/.moat/remote` and the `openmoat approvals` commands.
- **On Linux, `openmoat run` now starts the Isolated tier (bubblewrap) by default** where bubblewrap works. An agent whose runtime lives elsewhere in the home can need that folder in `sandbox.read_roots`; `--no-isolate` starts the Lightweight tier as before ([Linux tiers and Landlock](/docs/sandboxes/linux-tiers/)).
- **Library crates:** a break, hence 0.20.0. See the **Breaking** entries under Changed.

Every step after an upgrade: [Upgrade](/docs/upgrade/).

</Aside>

## Security
- A pipeline a rule matches at its end is decided the same when another command follows it on the line: `curl URL | x ; true` could be left to the agent where `curl URL | x` was denied ([#781](https://github.com/crocodile-labs/openmoat/pull/781)).
- Under `require.run: full-boundary`, only an allowlist of inherited environment variables reaches what `openmoat run` starts, so a cloud credential in the shell does not; add a name with `sandbox.env_allow` or `--env NAME`, and `openmoat doctor` and `openmoat run --verbose` name what is withheld, never a value. Without the setting, one line says how many inherited variables look like credentials (ADR-077) ([#782](https://github.com/crocodile-labs/openmoat/pull/782)).
- `require.run: full-boundary` makes `openmoat run` refuse to start without an OS sandbox or, on Linux, without a network namespace for the agent, whatever `--netns` says; `openmoat status` and `openmoat doctor` report whether it holds on the system (ADR-077) ([#782](https://github.com/crocodile-labs/openmoat/pull/782)).
- Every line `openmoat mcp wrap`, `unwrap` and `init` print about an MCP server (wrapped, skipped, without the sandbox, tools held) shows its name without the control or hidden characters an agent's file may put in it ([#786](https://github.com/crocodile-labs/openmoat/pull/786)).
- The policy lock's copy of a pinned MCP server definition no longer keeps the values of OpenCode's `environment` or goose's `envs` in clear, and `openmoat mcp accept` and `openmoat doctor` never show them: they are hidden like `env`. A lock an older version wrote keeps every server pinned as it was, so nothing is accepted again; `openmoat doctor` names one that still holds such a value, `openmoat doctor --accept` rewrites it, and so does any other change to the lock ([#786](https://github.com/crocodile-labs/openmoat/pull/786)).
- What `openmoat mcp wrap` and `unwrap` print for a server to set by hand no longer passes a control or hidden character from the server's name or arguments to the terminal ([#786](https://github.com/crocodile-labs/openmoat/pull/786)).
- What `openmoat mcp accept` and `openmoat doctor --accept` show before asking to accept an MCP server definition, and doctor's line for each changed definition, no longer pass a control or hidden character from the server's name, keys or arguments to the terminal ([#788](https://github.com/crocodile-labs/openmoat/pull/788)).
- A key or a variable's name with line breaks in an MCP server definition can no longer add lines of its own to what `openmoat mcp accept` shows before it asks, so it cannot push the real change off the screen or show another server's ([#788](https://github.com/crocodile-labs/openmoat/pull/788)).
- What `openmoat status`, `openmoat doctor` and `require.run: full-boundary` say about each MCP server, and doctor's line on a server's held tools, name the server without its control or hidden characters wherever the text is printed ([#788](https://github.com/crocodile-labs/openmoat/pull/788)).
- `~/.moat/delivery.yaml`, which decides where the audit log is sent, is pinned by the policy lock like the policy: a file no person accepted with `openmoat doctor --accept` stops every hook call and sends nothing. Its keys and tokens must be files inside `~/.moat/delivery/` or keychain items (`env:` is refused), the background run gets a cleared environment (no `SSL_CERT_FILE`, no proxy variables), plain `http` goes to loopback only, and link-local, cloud metadata and non-unicast addresses are refused on every resolved address (ADR-081) ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- A sink's header secret is masked in what is delivered in every form an event could hold it, not only as the full header value: the bare token after a `Bearer ` prefix, the token with its spaces trimmed, and for `Basic` credentials the decoded `user:password` and the password alone, so `echo $TOKEN` in an agent's call is not sent to the collector in the clear ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- `kernel-self` denies agents and sandboxed commands reading `~/.moat/delivery/` (and `delivery/` in any `.moat/`), where audit delivery's webhook key and collector token live, so `cat ~/.moat/delivery/webhook.key` is denied; a key or token file elsewhere in the state directory, which the agent may read, is refused ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- The default policy's `kernel-self` rule denies agents reading `~/.moat/remote` (each approval channel's credential under `~/.moat/remote/<channel>/`, and the key that signs requests, answers and the approver list) and running any `openmoat approvals` command, by either name, by path and under the pseudo-terminal wrappers (ADR-078) ([#790](https://github.com/crocodile-labs/openmoat/pull/790)).
- Remote approval: a call longer than the 1500 characters an approver is shown can only be denied from another device, on every channel; the request records that it was cut, under its signature, and the guard uses no approval for such a request (ADR-078) ([#790](https://github.com/crocodile-labs/openmoat/pull/790)).
- Remote approval: a call whose shown text redaction changed (a value that looks like a secret, a URL's user and password) can only be denied from another device, since the hidden part may be what runs; the approver is told to approve it at the terminal (ADR-078) ([#790](https://github.com/crocodile-labs/openmoat/pull/790)).
- Remote approval: an approval is bound to every argument the agent's tool call carries, hashed as canonical JSON, not only to the fields OpenMoat reads, so an approved notebook edit, a host's own write or replace tool, or an unknown tool's call cannot be swapped for one with other content (ADR-078) ([#790](https://github.com/crocodile-labs/openmoat/pull/790)).
- Remote approval: when a call's approval was used but the call was then refused because its audit row could not be written, the call stays denied and the approver is told "approved, but the call was refused" with the reason, and it is recorded, instead of the approval vanishing silently (ADR-078) ([#790](https://github.com/crocodile-labs/openmoat/pull/790)).
- Remote approval: a channel's chunked HTTPS response with a chunk size past the 4 MiB response limit is refused, where a size near the largest number could overflow and stop `openmoat approvals listen` (ADR-078) ([#790](https://github.com/crocodile-labs/openmoat/pull/790)).
- Remote approval: `openmoat approvals listen` answers every reply of a poll even when one fails (it is logged), and only then moves past them on the channel's server, where one failing reply used to drop the rest of that poll (ADR-078) ([#790](https://github.com/crocodile-labs/openmoat/pull/790)).
- Remote approval: a line break in the call is shown as a line break marked with `⏎`, not as `?`, so `ls foo` followed by `rm -rf ~/work` reads as the two commands it is (ADR-078) ([#790](https://github.com/crocodile-labs/openmoat/pull/790)).
- `openmoat run` on Linux no longer lets a command reach a pathname datagram socket outside the sandbox (`/dev/log`, journald's socket) through a datagram socket pair, which it could connect again or send to with an address: the seccomp filter now allows `socketpair()` only for stream and sequenced-packet sockets, which Node, Python and Chromium use, and a datagram pair fails with `EPERM` ([#794](https://github.com/crocodile-labs/openmoat/pull/794)).
- Where the kernel has Landlock ABI 9 (Linux 7.1), `openmoat run` also has Landlock refuse connecting or sending to any pathname Unix socket made outside the sandbox (`EACCES`), beside the seccomp filter; an older kernel keeps the filter alone, as before (ADR-082) ([#794](https://github.com/crocodile-labs/openmoat/pull/794)).

## Added
- `openmoat status` and `openmoat doctor` name the exact `openmoat run` command for each agent OpenMoat writes no OS sandbox for, or say why there is none on this system or for that agent (ADR-076) ([#779](https://github.com/crocodile-labs/openmoat/pull/779)).
- `openmoat status` and `openmoat doctor` show each MCP server OpenMoat can read as protected or unprotected, with why; under `require.run: full-boundary` an unprotected local server fails the requirement, which is reported because the agent starts its servers itself (ADR-077) ([#782](https://github.com/crocodile-labs/openmoat/pull/782)).
- `openmoat mcp wrap` reads each agent's own form of a server: OpenCode's single `command` list is wrapped and undone in place, and goose's `cmd` and `args` are read, so `openmoat status` and `openmoat doctor` report goose's extensions. A YAML file or an OpenCode file with comments is named with what to set by hand and no longer stops the other servers; a goose extension of inline Python is named as having no command to wrap ([#785](https://github.com/crocodile-labs/openmoat/pull/785)).
- Live audit delivery to a SIEM or log collector: `~/.moat/delivery.yaml` names up to four sinks, OTLP/HTTP logs (JSON) or an HTTPS webhook whose bodies are signed with HMAC-SHA-256 (`X-OpenMoat-Signature`). The hook never waits for it: after answering, the guard starts a detached delivery run, which sends the events after each sink's place in the audit log, every text masked again. A sink that fails is tried again with growing waits; one that answers with an error trying again cannot fix is paused; one that falls more than `max_backlog` events behind is told which events it missed, and the skip is recorded in the audit log (`audit-delivery-overflow`). New commands `openmoat audit deliver status`, `test` and `flush` (`docs/DELIVERY.md`, ADR-081) ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- One oversized event no longer stops audit delivery for good: each event is trimmed after masking to the batch size and at most 256 KiB (long texts cut with a `…[openmoat trimmed N bytes]` marker), a `413` answer halves the events per request, and one event that still gets `413` alone is skipped, recorded (`audit-delivery-too-large`) and sent as a gap, instead of pausing the sink ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- A delivery run that fails as a whole (the audit log or the policy cannot be read) no longer makes every hook call start another: the guard waits a minute, doubling to 15 minutes while it keeps failing, and after any run it starts the next one a second later at the soonest ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- An OTLP collector that answers `200` but rejects records (`partial_success`) no longer counts as having taken them: the records are not sent again, as the OTLP specification asks, but the loss is recorded in the audit log (`audit-delivery-partial`, with the count and the collector's message, masked) and sent to the collector as a gap with the next request ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- A sink that has accepted no event yet (a first try that failed, was refused or found nothing to send) no longer stops audit delivery: its state file holds the place before the first event as `0`, which the next run now reads back instead of refusing as an event id ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- `openmoat doctor` names each agent that runs a tool call when OpenMoat's hook cannot start, crashes or times out ("fails open"), with the way out: start it with `openmoat run` and add `require.run: full-boundary` to the policy. `openmoat status --format json` carries each agent's `hook_failure` facts and their sources, and `docs/LIMITS.md` has a per-agent "If the hook fails" table generated from them (ADR-079) ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- The weekly latest-agent job makes OpenMoat's hook fail (exit 1, binary gone) under each real agent it starts, and fails when an agent runs a call its facts say it blocks (ADR-079) ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- Cline CLI counts as running the call when OpenMoat's hook fails: OpenMoat's script blocks it when `openmoat` is missing or crashes, but Cline runs the call when the script itself cannot start (no `sh`, as on native Windows), so `openmoat doctor` names Cline as failing open rather than promising a block ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- `openmoat run` takes a snapshot of the project's files before the agent starts and after it exits, into OpenMoat's own store outside the project (`--no-snapshot` opts out, recorded); `openmoat restore` puts them back after showing each change and asking, and takes an undo snapshot first; `openmoat snapshot` takes, lists (`--list`) and prunes (`--prune`) them. Secrets and other paths a deny rule names, ignored files and files over 5 MiB are left out and named; both commands are person-only, and the default policy denies them, and reading or changing the store, to agents (ADR-085) ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- A snapshot holds each file's bytes as they are and a restore writes back those bytes, whatever the project's `.gitattributes` say: line-ending conversion (`text`, `eol`), `ident` and `working-tree-encoding` are off in OpenMoat's store, so a `.gitattributes` an agent plants can neither change what comes back nor make a snapshot fail ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- Every `openmoat run` records its own start snapshot, even when the files are as the previous snapshot holds them, so a plain `openmoat restore` goes back to the start of the last run and never undoes an earlier run's work as well ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- Two `openmoat run` in one project, or a run beside a person's `openmoat snapshot` or `openmoat restore`, no longer race on the snapshot store: taking, pruning and restoring hold the store's lock, each snapshot is staged in its own index file, and pruning drops only unreferenced files older than an hour ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- `openmoat restore` cannot be made to write or delete outside the project by a process of the agent that swaps a checked folder for a link while the restore runs: on macOS and Linux every write, rename and delete is made relative to the folder it checked, held open (`openat` with `O_NOFOLLOW`); on Windows each folder is checked again right before each change and any change refuses the path (ADR-085) ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- `openmoat restore` no longer deletes a file that was there but ignored when the snapshot was taken (an agent that stops ignoring `notes.local` cannot get it deleted): each snapshot lists the ignored paths that existed, and the restore leaves them as they are and says so ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- A call held for review can be approved from your phone: `openmoat approvals connect telegram` connects a Telegram bot you made, `openmoat approvals allow telegram:<user-id>` names who may approve, and while `openmoat approvals listen` runs each review is sent there with Approve and Deny buttons. An approval lets that exact call (agent, session, folder, command or file and its content, and the rules that held it) run once, within 5 minutes by default; a deny is never sent, and every failure leaves the review as it was. `openmoat approvals status`, `test`, `remove` and `disconnect` complete it; nothing changes without a channel. Channels are built to be added one folder at a time: each declares what it can do, and OpenMoat shapes the message to it (buttons, or reply codes to send back, and Deny only when a channel cannot show the whole call); approver ids carry the channel's name, so the same user number on two services never counts twice. docs/APPROVALS.md says how to add one (ADR-078) ([#790](https://github.com/crocodile-labs/openmoat/pull/790)).
- Short-lived brokered secrets (preview): a secret's `source: { command: { run: [...], lifetime: 15m } }` names a program, such as a cloud CLI's token command, that `openmoat proxy` runs for the value, uses it for at most `lifetime` (1 minute to 12 hours, or less when the program prints an expiry) and runs again before it ends, on a thread of its own. Past its deadline a request that needs the value is refused before anything is sent and recorded as `proxy-secret-expired`; a stale value is never sent. The program runs only when a deny `fs.write` rule covers it or only an administrator can change it, never from `/tmp`, pinned by its SHA-256 for the life of the proxy, with no input, a bare environment, a 30-second limit and 64 KiB of output; its output is never quoted and every value it gave is masked in the audit log. `openmoat guard`, audit delivery and Claude Code's broker never run it, and a repository policy or pack cannot add one (`docs/POLICY.md` §2.2, ADR-087) ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- A `command` source's program starts in `/`, never in the agent's project, with an empty home of its own under OpenMoat's state folder; `home: user` gives it your home for a tool that keeps its login there ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- A `command` source's program finds tools in the system's folders only, never its own; every folder above it, up to your home, must be kept from the agent as the file is, and a script's interpreter must pass the same check and is pinned too (`#!/usr/bin/env` is refused). The example is now Vault's CLI, not `gcloud`, whose Python loads from folders you can write ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- The proxy runs a private copy of the bytes it hashed, checked again before each run, never the file at the program's path; a deny rule counts as proof only outside the project and `openmoat run`'s write roots, where only root ownership does ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- On macOS and Linux the time limit ends a `command` source's whole process group, and its output is read with a deadline, so a child it left holding its output neither outlives the run nor keeps a thread of the proxy waiting ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- A `command` source is renewed from the lifetime its value actually got (the shorter of `lifetime` and the expiry it printed), a fifth of it before the end, at least a minute ahead and at most once a minute after an answer, each secret on its own thread; a program that printed an expiry shorter than `refresh_before` was run on every look ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- Under `openmoat run`, a repository policy's deny rules no longer count as proof that the agent cannot change a `command` source's program; only your own policy's do ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- `openmoat guard`'s audit rows do not mask a `command` source's value: OpenMoat does not write the values to a file for it, which would be a copy on disk of the tokens the source keeps short-lived; LIMITS.md says so ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- `openmoat doctor` on Linux names the kernel's Landlock ABI and what `openmoat run` applies from it (each ABI from 4 to 12 with `--verbose`: used, available but not used and why, or not available and what holds instead); `openmoat sandbox show` and `openmoat run --verbose` show the same, `sandbox show --format json` has it under `lightweight.landlock.abi`, and every Linux run writes it to the audit log (rule `run-landlock-abi`) before the agent starts (ADR-082) ([#794](https://github.com/crocodile-labs/openmoat/pull/794)).
- `docs/PROTECTION.md`: one row per agent on Linux, macOS and Windows of what protects its calls (the hook as protected, preview or none; what the agent does when the hook fails; its own sandbox; the tier `openmoat run` starts it in; its MCP servers; what a command can read inside a run), with the tests and weekly real-agent runs behind each claim. It is generated from the agents' facts and from end-to-end tests marked `// protection:`, a claim nothing backs reads `no evidence yet` and its summary `preview`, and the docs test fails when the page or a mark is wrong; `openmoat doctor --verbose` ends with a pointer to it (ADR-079) ([#795](https://github.com/crocodile-labs/openmoat/pull/795)).

## Changed
- `docs/COVERAGE.md` now shows all ten risks of the OWASP Top 10 for Agentic Applications (2026), each marked covered, partial or out of scope with a one-line reason that says what is left out. Risks no fixture class maps to show no counts, and a test keeps a row for every risk from ASI01 to ASI10 ([#777](https://github.com/crocodile-labs/openmoat/pull/777)).
- The README shows OpenMoat's own MoatBench result for 0.19.0 from the benchmark's own repository; the older comparison with other tools is removed ([#778](https://github.com/crocodile-labs/openmoat/pull/778)).
- At a terminal, `openmoat init` now offers to run the agents' stdio MCP servers through `openmoat mcp proxy`, shows the change and asks before writing; `--no-mcp-proxy` opts out, a no is remembered per definition, and without a person nothing is rewritten (ADR-076) ([#779](https://github.com/crocodile-labs/openmoat/pull/779)).
- **Breaking** `openmoat-hosts`: `HookLayout::Plugin` holds a `&'static dyn PluginConfig`, the new trait that edits a host's plugin configuration, instead of the plugin's `&'static OwnedFile` (`PluginConfig::plugin` returns that file); the `OPENCLAW_CONFIG_FILE`, `OPENCLAW_PLUGIN_ID`, `OPENCLAW_STATE_DIR_NAME` and `OPENCLAW_STATE_DIR_VARIABLE` exports are gone, since what they named is in the host's spec ([#780](https://github.com/crocodile-labs/openmoat/pull/780)).
- **Breaking** `openmoat-core`: `SandboxSettings` has a new public field `env_allow`, and `openmoat-hosts`: `HostSpec` a new public field `run_env`, which breaks code that builds them field by field ([#782](https://github.com/crocodile-labs/openmoat/pull/782)).
- **Breaking** `openmoat-core`: `Require` has a new public field `run` (`Option<RunBoundary>`), which breaks code that builds it field by field ([#782](https://github.com/crocodile-labs/openmoat/pull/782)).
- **Breaking** `openmoat-hosts`: the `CONTINUE_ENV` export is gone; `HostSpec::speaks_variable` holds the variable and `Host::caller_variable` returns it ([#785](https://github.com/crocodile-labs/openmoat/pull/785)).
- Generic code names no agent for the lock's settings pins, Claude Code's secret masking rows in `sandbox show` and `doctor`, or the variable that says the Continue CLI runs the hook: each comes from the sandbox backend or the host's spec. The lock's file format, what it pins and the output are unchanged ([#785](https://github.com/crocodile-labs/openmoat/pull/785)).
- The policy lock digests a settings file it pins by OpenMoat's part with the backend of the host whose file it is, found by the file's name, rather than with the first backend that pins by part; what the lock pins and its digests are unchanged ([#786](https://github.com/crocodile-labs/openmoat/pull/786)).
- Antigravity CLI is checked against a real `agy`: the weekly `latest agents` job records what agy loads and runs ([#789](https://github.com/crocodile-labs/openmoat/pull/789)), and in its run of 2026-11-12 ([43254846914](https://github.com/crocodile-labs/openmoat/actions/runs/43254846914)) a real `agy` on Linux and macOS ran OpenMoat's `PreToolUse` hook, which denied a read of a planted key, and blocked the call when the hook binary was missing and when it exited 1 without output. `docs/PROTECTION.md` shows its hook as protected on Linux and macOS, and `openmoat doctor` names it as failing open only when the hook times out, which agy does not document and the job does not try; the weekly job now fails if a later `agy` runs a call when the hook fails.
- The OWASP agentic table in `docs/COVERAGE.md` now states its evidence: end-to-end tests marked for a risk count beside the fixtures, a new section lists each risk's test names and fixture ids, and a risk nothing tests reads `not tested` whatever is claimed for it; the conformance suite fails when a risk claimed as covered or partly covered has no evidence, and when the document differs from what it generates (ADR-079) ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- **Migration:** `openmoat run` on Linux starts the Isolated tier (bubblewrap) by default where bubblewrap works, so commands the agent starts can no longer read `.env` or write `.git/hooks` and `.moat` in the project. The agent sees only the project, the read roots, its executable, the `--write` paths and an empty temp directory; an agent whose runtime lives elsewhere in the home can need that directory in `sandbox.read_roots`. Where bubblewrap is missing or blocked it says why on every start, records `run-isolation-unavailable` in the audit log and starts the Lightweight tier as before. `--no-isolate` starts the Lightweight tier on purpose and records `run-no-isolate`; `openmoat doctor` says which tier applies in its OpenMoat section, without `--verbose`. Under `require.run: full-boundary` the Isolated tier is required on Linux and `--no-isolate` is refused (ADR-080) ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- An MCP server started with `openmoat mcp proxy --sandbox` runs in the Isolated tier on Linux too, so a path outside the project and the read roots is not there for it at all, rather than there and denied ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- The guard's p95 budget is 20 ms for its own decision on Linux CI runners and 45 ms on macOS ones, where the same binary measures 17 to 37 ms median; a row over it warns. The latency check now times the commit before on the same runner on every run, pushes to `main` included, instead of holding `main` to a fixed limit that failed macOS runs whose guard code had not changed, and both latency scripts report the median, p95 and p99 (ADR-080) ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
- **Breaking** `openmoat-hosts`: `HookRequest` has a new field, `input`: the call's whole tool arguments as canonical JSON (keys sorted, no whitespace), `None` for an event without a tool call ([#790](https://github.com/crocodile-labs/openmoat/pull/790)).
- **Breaking** `openmoat-core`: `SecretSource` has a `Command` variant (`SecretCommand`), so an exhaustive `match` on it needs an arm, and `SecretCommand::home` (`SecretCommandHome`); `SecretSource::proxy_only` and `describe`, and `lint::write_denied`, are new. `openmoat-proxy` adds `Broker::rotation`, `Rotation` and `RULE_SECRET_EXPIRED`; `openmoat-audit` adds `Store::set_secrets` ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).

## Fixed
- When `openmoat mcp proxy` refuses every call of a server that was not started, a request id holding U+2028 or a similar line separator is escaped in the reply, so no reader that splits lines on it sees two messages ([#785](https://github.com/crocodile-labs/openmoat/pull/785)).
- `openmoat status` and `openmoat doctor` no longer advise `openmoat mcp wrap` for a goose extension of inline Python, which cannot be wrapped, and `openmoat mcp wrap` no longer warns about an OpenCode entry that names no program, such as `{"enabled": false}` or a `url` with no `type` ([#786](https://github.com/crocodile-labs/openmoat/pull/786)).
- `openmoat mcp wrap <server>` and `unwrap <server>` exit 64 when a server asked for by name is left as it is (one OpenMoat cannot put behind the proxy, or one with a change nobody accepted) instead of printing "no stdio MCP server to wrap" and succeeding, and a file that cannot be read or parsed, or no longer holds the server, fails the command again rather than being named as one to set by hand ([#786](https://github.com/crocodile-labs/openmoat/pull/786)).
- A wrapped MCP server's variables reach it under `require.run: full-boundary` for OpenCode (`environment`) and goose (`envs`) as they do under `env`, and a definition is read in the form its agent reads it: a stray `cmd` beside `command` and `args` no longer leaves a wrapped server without its `--host` or stops `openmoat mcp unwrap` and `openmoat uninstall` from restoring it ([#786](https://github.com/crocodile-labs/openmoat/pull/786)).
- A long agent session that moves to another folder no longer has every call denied with `kernel-error` while OpenMoat reads the session's earlier calls again: the session's taint is kept for every directory, and only calls recorded without a working directory keep a directory's own ([#787](https://github.com/crocodile-labs/openmoat/pull/787)).
- Working out a session's taint classifies each earlier call once instead of twice, so a session read again after an upgrade or a policy edit catches up in fewer calls ([#787](https://github.com/crocodile-labs/openmoat/pull/787)).
- `openmoat doctor` lists the calls the guard denied in the last day because it could not decide them (`kernel-error`), with the latest one's time, agent and reason (not its session id) and what to run next, so it no longer says "All good" while the guard refuses every call ([#787](https://github.com/crocodile-labs/openmoat/pull/787)).
- `openmoat doctor --accept` over a drifted lock no longer exits 64 on the line about MCP server values an older version kept in clear: the re-pin has already written the lock without them, and the line is now decided from the lock as it is on disk ([#788](https://github.com/crocodile-labs/openmoat/pull/788)).
- `openmoat mcp wrap <server>` and `unwrap <server>` exit 64 with a line naming the server when the name matches no server in the agents' own files (a typo), and `wrap` does so for a named remote server, which has nothing to wrap, instead of printing "no stdio MCP server to wrap" and succeeding; a named server already wrapped still succeeds ([#788](https://github.com/crocodile-labs/openmoat/pull/788)).
- Under `openmoat run`, Claude Code's Bash tool no longer fails on every call when OpenMoat is installed under the home directory (`~/.cargo/bin`, Homebrew on Linux): Claude Code's sandbox, with the `blockReadsOutsideWorkingDirectories` that `openmoat init` sets, hides that directory, and the tool-shell wrapper was a link to it. The wrapper's directory in the system temp directory now holds a copy of the binary, so it starts with nothing outside that directory (ADR-075) ([#789](https://github.com/crocodile-labs/openmoat/pull/789)).
