- Breaking for the library crates' API only; the `moat` command is unchanged.

File provenance taint, package name checks and release age, agents cannot read OpenMoat's state, audit anchors, signed policy packs, and fixes. Breaking for the library crates' API; the moat command is unchanged for users.

## Security
- Session taint follows the files a tainted session writes. A file written by a session that read untrusted content is recorded in the audit log (with the content's hash for `Write`); a later session that reads or runs it (`Read`, `cat`, `source`, `bash run.sh`, `./run.sh`, `python x.py`) while it still holds that content is tainted too, so its writes to CI, build and agent files ask, with a reason naming the file and the session that wrote it. No new asks of its own; a clean `Write` of the file clears it, and `taint: { provenance: false }` turns it off ([#577](https://github.com/crocodile-labs/openmoat/pull/577)).
- An install of a package whose name is one typo or a common trick away from a popular package (`pip install reqeusts`, `npm i lodahs`, `npm i react_dom`, `pip install python-requests`) asks, naming the package that was probably meant (`package-near-miss`). The check is offline, against a bundled list of popular names for npm, PyPI, crates.io, RubyGems and Go; popular names and names that resemble none are decided exactly as before. `moat allow --always` for such an install also answers its near-miss ask. Existing policies get the group with `moat policy upgrade` ([#577](https://github.com/crocodile-labs/openmoat/pull/577)).
- `moat run` keeps npm and uv off package versions published in the last 7 days (`npm_config_before`, `UV_EXCLUDE_NEWER`), so a malicious release taken down within days does not reach the agent; `sandbox.package_min_release_age_days` sets the days and `0` turns it off. A cut-off you set yourself is kept, and a project with a `uv.lock` is left alone ([#577](https://github.com/crocodile-labs/openmoat/pull/577)).
- `kernel-self` denies the agent reads of OpenMoat's state beside the policy: the audit log (`audit.db*`), `policy.lock`, `hosts.json`, `approvals.json`, `trust.json`, `allowed_signers` and the MCP pins in `mcp/`, wherever `MOAT_HOME` puts them. The host sandboxes and `moat run` carry the same denies; `policy.yaml` stays readable. `sqlite3 -readonly ~/.moat/audit.db` is now denied rather than left to the agent. Existing policies get it with `moat policy upgrade` ([#577](https://github.com/crocodile-labs/openmoat/pull/577)).
- A policy pack is installed only when its OpenSSH signature verifies against a key a person trusted, and is pinned by the lock, so a pack changed after install denies every call (`kernel-integrity`) ([#577](https://github.com/crocodile-labs/openmoat/pull/577)).
- `moat audit anchor` is denied to agents (`kernel-self`). Existing policies get it with `moat policy upgrade` ([#577](https://github.com/crocodile-labs/openmoat/pull/577)).

## Added
- `moat audit anchor --git <repo>` commits the audit log's head (event, hash, time) on `refs/moat/anchors` in a repository you name, and `--file <path>` appends it to a file you keep; nothing is pushed or sent anywhere. `moat audit verify --against <repo|file>` checks today's log against every anchor and fails, naming the first anchor whose event was deleted or rewritten. `moat doctor` shows when you last anchored ([#577](https://github.com/crocodile-labs/openmoat/pull/577)).
- Signed policy packs: `moat policy trust-key <key.pub> --name <who>` trusts an SSH key to sign policy, `moat policy install <pack.yaml> [--sig …]` verifies the pack with the system `ssh-keygen -Y verify` (namespace `openmoat-policy`) and merges its rules as `pack:<name>:<id>`, and `moat policy remove` takes it out. With `require_signed_repo_policy: true` in the policy, a repository policy's allow rules apply only when it is signed by a trusted key (`.moat/policy.yaml.sig`): a signed one needs no `moat trust`, and an unsigned one, or one signed by another key, is not trusted even after `moat trust`. Without it nothing changes ([#577](https://github.com/crocodile-labs/openmoat/pull/577)).

## Changed
- The push check gives git 10 s instead of 2 s before a push asks as unchecked (`push-unchecked`): starting git can take seconds on Windows and on a loaded machine ([#577](https://github.com/crocodile-labs/openmoat/pull/577)).
- The audit database moves to schema version 4 to record file provenance. Older `moat` builds cannot open a version-4 audit database ([#577](https://github.com/crocodile-labs/openmoat/pull/577)).
- `moat run`'s first line names its proxy's loopback port again (`network only through OpenMoat's proxy on 127.0.0.1:<port>`) ([#578](https://github.com/crocodile-labs/openmoat/pull/578)).
