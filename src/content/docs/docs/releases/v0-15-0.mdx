Released 2026-11-05. [GitHub release v0.15.0](https://github.com/crocodile-labs/openmoat/releases/tag/v0.15.0).

<Aside type="caution" title="Upgrading">

- **Run `openmoat policy upgrade`** in your own terminal for the changed default rules: card ids in URLs, queries and searches are no longer denied, writes to `.githooks`-style folders and Cline's workspace hooks need review, `git config <name>` reads are allowed, and an agent running `openmoat guard` itself is denied. It shows the diff and asks before writing.
- **Codex:** run `openmoat init` again, then trust OpenMoat's hook in Codex's `/hooks`. The hook now also covers `read_mcp_resource` and `view_image`, so its matcher changed.
- **Upgrading from 0.13:** the audit log's move to schema 8 no longer copies the log, so a large log no longer blocks calls after the upgrade.
- **Library crates:** `openmoat-hosts` gains the public field `HookRequest::sandboxed` and new `HostSpec` fields. See the [changelog](https://github.com/crocodile-labs/openmoat/blob/main/CHANGELOG.md).

Every step after an upgrade: [Upgrade](/docs/upgrade/).

</Aside>

## Security

- **Codex and Cursor decide a command from the session's project.** The tool's working directory is chosen by the model, so it no longer sets the project: a command run from outside the session's project (Codex's `workdir`, a Cursor `cwd` outside every workspace root) is decided as running in the session's directory. A write from `~/Library/LaunchAgents` is checked as that path ([#726](https://github.com/crocodile-labs/openmoat/pull/726)).
- **Codex: a bare shell or REPL needs review.** A command that starts a shell, REPL, editor or login with no script or command of its own (`bash`, `python3`, `node`, `sqlite3 db`, `ssh host`) needs review, because Codex types later input into it with `write_stdin`, which runs no hook. `bash x.sh`, `python3 x.py` and `ssh host cmd` are decided as before ([#726](https://github.com/crocodile-labs/openmoat/pull/726)).
- **Codex: `read_mcp_resource` and `view_image` are checked** as the resource or image they read ([#726](https://github.com/crocodile-labs/openmoat/pull/726)).
- **Hermes Agent:** "always" on a review approves that call again and never another call held for the same reason. A relative file path is checked against the directory Hermes started in instead of always needing review; a path that climbs out (`..`) and a `terminal` call that moves the shell outside that directory need review, and the message names the file and whether it is read or written ([#726](https://github.com/crocodile-labs/openmoat/pull/726)).
- **Gemini CLI:** `grep_search` and `glob` without a `dir_path`, and `read_many_files`, are checked over the working directory and the `context.includeDirectories` of your settings instead of always asking ([#726](https://github.com/crocodile-labs/openmoat/pull/726)).
- **Cursor:** a command Cursor runs in its own sandbox that no rule decides is allowed, as Cursor would run it, while OpenMoat's `sandbox.json` is installed; it no longer asks ([#726](https://github.com/crocodile-labs/openmoat/pull/726)).
- **Cline CLI:** the payload limit counts Cline's two copies of a call's arguments once, so a file is refused at the same size as on other agents, with a message that says to write it in parts ([#726](https://github.com/crocodile-labs/openmoat/pull/726)).
- **`openmoat init`** says when it moves your own whole-file hook (Cline's `PreToolUse`) aside, and `init` and `uninstall` keep a host file's permission bits ([#726](https://github.com/crocodile-labs/openmoat/pull/726)).
- **Git hook folders need review.** Writes to the folders a repository's `core.hooksPath` usually names (`.githooks/`, `.git-hooks/`, `githooks/`, `git-hooks/`, `scripts/git-hooks/`) need review (`runs-later`) and mark the session, because git runs those files on the next commit or push. Folders merely named `hooks` (React hooks, docs) stay ordinary writes ([#727](https://github.com/crocodile-labs/openmoat/pull/727)).
- **Cline's workspace hooks need review.** Writes to `.clinerules/hooks/` and `.cline/hooks/`, every file of which Cline runs on each tool call, and renames onto `.clinerules`, `.cline` or their `hooks` folders need review (`runs-later`). Rules files in `.clinerules/` stay ordinary writes ([#727](https://github.com/crocodile-labs/openmoat/pull/727)).
- **A quote or a backslash ends a variable's name,** as in the shell: `d=~/.ssh/id; cat "$d"_rsa` is a read of `~/.ssh/id_rsa` and denied by `secrets-paths`, and `echo "$GITHUB_TOKEN"x` reads `GITHUB_TOKEN` (`env-secrets`). Before, they were read as unknown variables and deferred ([#727](https://github.com/crocodile-labs/openmoat/pull/727)).
- **Editors count as writes.** `vi`, `vim`, `nvim`, `nano`, `emacs` and `code` save the file they open, so `vim /usr/local/bin/openmoat` and `nano ~/.moat/policy.yaml` are denied by `kernel-self` and `nvim ~/.zshrc` by `shell-rc`. An editor on a project file keeps its verdict ([#727](https://github.com/crocodile-labs/openmoat/pull/727)).
- **More passwords are masked in the audit log:** `mysql -p<password>`, `PGPASSWORD=`, `MYSQL_PWD=` and other environment names ending in `PASSWORD`, `_KEY`, `_SECRET`, `_TOKEN` or `_AUTH`, `sshpass -p`, `docker login -p`, `redis-cli -a`, `openssl -k` and `-pass pass:`, `zip -P`, `htpasswd -b`, `Cookie:` and `Set-Cookie:` values, `aws configure set aws_secret_access_key`, Slack and Discord webhook URLs, and a key given as the user part of a URL. The same flags of other programs (`cargo test -p`, `ssh -p`, `mkdir -p`) keep their values ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- **An agent cannot run `openmoat guard` or `openmoat mcp proxy` itself** (`kernel-self`). Only a host runs them, so an agent cannot write audit rows, MCP tickets or a session's proxy credential for calls it made up. `--help` still works ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- **`openmoat allow --last` and `openmoat policy upgrade`** (and `--undo`) refuse to re-pin when a pinned file or the lock changed while they waited for your answer ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- **Claude Code with `blockReadsOutsideWorkingDirectories` off:** the guard again works out whether the sandbox is in place, so code a session wrote is held for review at once ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- **`openmoat run` on macOS** also denies hard links to every path it denies reading or writing, so a sandboxed command cannot link `~/.moat/proxy.key` or `audit.db` into the project ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).

## Added

- **`@openmoat/sdk` is on npm:** `npm install @openmoat/sdk`. The release workflow publishes it through npm's trusted publishing, with provenance, after the SDK's conformance tests pass ([#730](https://github.com/crocodile-labs/openmoat/pull/730)).

## Changed

- **Cline CLI limits are shown.** `openmoat status` and `doctor` print Cline's limits on a line of their own (`cline --yolo` runs no hooks; another hook or plugin can change a call after OpenMoat checked it; Cline runs the call when OpenMoat's script cannot start or is killed after 120 s), and name every other `PreToolUse` file in Cline's hook folders and every Cline plugin. `status --format json` lists them under `other_hooks` and gives each agent's `limit` ([#729](https://github.com/crocodile-labs/openmoat/pull/729)).
- **Linux: plain `openmoat run` says what it leaves open.** When it starts, it says on standard error that commands the agent starts can still read and write the project's `.env`, create `.envrc` and write `.moat` and `.git/hooks`, and that `openmoat run --isolate` closes this. `openmoat doctor` warns about the same, and `status`, `doctor` and `init` name `openmoat run --isolate` for an agent without a sandbox of its own ([#729](https://github.com/crocodile-labs/openmoat/pull/729)).
- **Agent login files: the gap is written down.** They are denied to the agent's own tool calls but stay readable to programs an allowed command runs, inside every OS sandbox too. ADR-054 (proposed) plans denying them in the host sandboxes that confine only the agent's commands ([#729](https://github.com/crocodile-labs/openmoat/pull/729)).
- **Library crates:** `openmoat-hosts`' `HookRequest` has a new public field `sandboxed`, plus new helpers and `HostSpec` fields. See the [changelog](https://github.com/crocodile-labs/openmoat/blob/main/CHANGELOG.md) ([#726](https://github.com/crocodile-labs/openmoat/pull/726)).

## Fixed

- **Card ids are no longer denied.** A 13 to 19 digit number counts as a card only in a card's context: the value of a field named like a card's (`card`, `cardNumber`, `cc`, `pan`, `card[number]`), or sent beside a security code or expiry such as `cvv` or `exp`. A GitHub repository or job id in an API path, an order id or a number in a search is no longer denied. Card numbers in printed groups (`4000 1234 5678 9017`) count wherever they are ([#727](https://github.com/crocodile-labs/openmoat/pull/727)).
- **`git config user.name` and other reads are allowed,** like `git config --get`, also after one scope option such as `--global`. A value after the name, or a subcommand such as `edit`, still needs review ([#727](https://github.com/crocodile-labs/openmoat/pull/727)).
- **`sed -n "$n"p f`** in a loop is read as the shell reads it and allowed like `sed -n "${n}p"` ([#727](https://github.com/crocodile-labs/openmoat/pull/727)).
- **Upgrading from 0.13 no longer blocks every call on a large audit log.** The first hook call used to copy the whole log to accept the `review` verdict and could run past the guard's time budget; the schema step now changes its check in place ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- **Loading the policy on each hook call is faster:** the old `ask` name check and policy merges no longer parse the policy a second time ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- **The audit log's last word matches the answer** when a call's MCP ticket or `openmoat run` link cannot be written after its row ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- **A crash while the guard decides** is denied in the format of the event (a `ConfigChange` is blocked as one), not always as a tool call ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- **goose:** `openmoat status` and `doctor` report goose not protected in a directory whose `.agents/plugins/openmoat` replaces OpenMoat's plugin, name the directory to remove, and warn about the hooks of the project's other plugins ([#729](https://github.com/crocodile-labs/openmoat/pull/729)).
