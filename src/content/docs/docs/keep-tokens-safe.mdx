<Aside type="note" title="Read this when">

Your agent needs an API token (GitHub, Stripe, an internal API) and you do not want it to be able to read or leak the value.

</Aside>

**Protects against** the agent reading, printing or leaking an API token it needs to use.

## What it does

An agent that can read a token can send it anywhere a prompt injection tells it to. A **brokered secret** stays with OpenMoat: programs the agent runs hold a placeholder such as `moat-secret:gh:placeholder`, and the real value is put into requests to one host only.

## Example

### GitHub in one command

<Steps>

1. **Add the secret, in your own terminal**

   ```bash
   openmoat secret add gh
   ```

   It brokers `GITHUB_TOKEN` for `api.github.com`, shows the change to your policy, asks `Apply? [y/N]`, then updates the agent sandbox.

2. **Start the agent from a shell that has the token**

   The value is read from the environment the agent starts in:

   ```bash
   export GITHUB_TOKEN="$(gh auth token)"   # in your terminal, not in the agent
   claude
   ```

3. **Use GitHub from the agent**

   `gh` and other tools inside the agent see the placeholder in `GITHUB_TOKEN`, and their requests to `api.github.com` carry the real token.

</Steps>

### Can the agent read the token?

| The agent tries | With `openmoat secret add gh` |
|---|---|
| `echo $GITHUB_TOKEN`, `printenv` | denied (`env-secrets`, `env-dump`) |
| `gh auth token`, `cat ~/.config/gh/hosts.yml` | denied (`secrets-paths`) |
| A program it runs reads `GITHUB_TOKEN` | gets the placeholder, not the value |
| Sends the placeholder to another host in a URL or a command's arguments | denied (`placeholder-egress`); worthless there anyway: the value is put in only for `api.github.com` (through `openmoat proxy`, such a request is also refused) |
| Commits a token and pushes it | denied (`push-secret`, see [GitHub and gh](/docs/github/#what-a-push-would-publish)) |

## Tokens sent to the wrong host

Even without a brokered secret, `token-egress` denies a well-known token (GitHub, OpenAI, Anthropic, AWS, Slack, Google, npm, GitLab) sent to a host that is not its service's, allowed hosts included: a GitHub token to `registry.npmjs.org` is denied, to `api.github.com` it is not. Each token's hosts, and what it does not see: [Tokens sent to the wrong host](/docs/keep-tokens-safe/token-egress/).

## Another service

Add the secret, and allow its host: a secret opens nothing by itself.

```bash
openmoat allow --site api.stripe.com
openmoat secret add stripe --host api.stripe.com --env STRIPE_API_KEY
```

The value goes in the `Authorization` header unless you pass `--header <name>`. `openmoat secret add` also checks that the agent cannot read the value's source, and adds a deny rule `secret-<id>` when none covers it: [Broker a token for another service](/docs/keep-tokens-safe/another-service/).

## Where it works today

Over HTTPS, the value is put in by Claude Code's own sandbox broker, for its sandboxed shell commands, and from 0.12.0 inside `openmoat run` for a secret that says `tls: terminate`, where `allow` rules also limit which requests may carry it (`openmoat secret add gh --tls-terminate --allow 'GET /repos/**'`): [Secrets over HTTPS, for some requests only](/docs/keep-tokens-safe/https-injection/). The standalone `openmoat proxy` and the other agents' sandboxes put it into plain-HTTP requests only, with `plain_http: true`. The details per agent: [Where it works today](/docs/keep-tokens-safe/where-it-works/).

## Commands

| Command | What it does | Example |
|---|---|---|
| `openmoat secret add gh` | Broker `GITHUB_TOKEN` for `api.github.com`; shows the diff and asks. Terminal only | `openmoat secret add gh` |
| `openmoat secret add <id> --host <host> (--env <NAME> \| --file <path>) [--header <name>]` | Broker another token for one host | `openmoat secret add stripe --host api.stripe.com --env STRIPE_API_KEY` |
| `openmoat secret add <id> … --tls-terminate [--allow 'METHOD /path']…` | Also put the value into HTTPS to the host inside `openmoat run`, and only into the requests the rules name; offers to make the proxy CA. Terminal only | `openmoat secret add gh --tls-terminate --allow 'GET /repos/**'` |
| `openmoat proxy ca init` | Make the CA `openmoat run`'s proxy decrypts HTTPS with, for the hosts of `tls: terminate` secrets only; asks, then pins it. Terminal only | `openmoat proxy ca init` |
| `openmoat secret list [--format json]` | Each secret's host, header and source, never the value, and whether a deny rule covers the source | `openmoat secret list` |
| `openmoat proxy` | Prints each secret's id, host, header and placeholder at start, and injects plain-HTTP secrets | `openmoat proxy` |
| `openmoat sandbox show` | What Claude Code's broker does with each secret | `openmoat sandbox show` |

## Settings

`openmoat secret add gh` adds exactly this entry:

```yaml
secrets:
  - id: gh                          # lowercase letters, digits, `-`; unique
    host: api.github.com            # one host, exact: lowercase DNS name or IPv4, no pattern or port
    header: Authorization           # the request header the value goes in
    source: { env: GITHUB_TOKEN }   # or { file: ~/.config/moat/gh } or { keychain: { service: moat, account: gh } }
    plain_http: false               # optional; true also injects into plain-HTTP (clear-text) requests
    # tls: terminate                # optional; inside openmoat run, decrypt HTTPS to the host and inject there
    # allow: ["GET /repos/**"]      # optional, with tls or plain_http: the only requests that get the value
```

A secret opens no host: its host still needs a `net` or `fetch` allow rule. `openmoat policy lint` warns when none names it, and when no deny rule covers the source. The rest: [POLICY.md §2.1](https://github.com/crocodile-labs/openmoat/blob/main/docs/POLICY.md#21-brokered-secrets-secrets).

## Limits

- **HTTPS injection works through Claude Code's own sandbox broker, and inside `openmoat run` for a `tls: terminate` secret.** Through the standalone `openmoat proxy` and the other agents' sandboxes a request over HTTPS keeps the placeholder, and the server rejects it ([above](#where-it-works-today)).
- **`token-egress` sees only prefixed token formats where the hook sees them**: not a token in an uploaded file, a here-document, a variable not on the command line, or an encoded or split token.
- **A variable you export before starting the agent** is still passed to the programs it runs, unless it is brokered under `openmoat run`.

More in [Limits](/docs/limits/).
