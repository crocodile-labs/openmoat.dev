<Aside type="note" title="Read this when">

You are setting OpenMoat up for the first time on a machine. Already have 0.7 or earlier (the `moat` command)? See [Upgrading from 0.7 or earlier](/docs/upgrade/#upgrading-from-07-or-earlier).

</Aside>

<Steps>

1. **Install openmoat**

   <Tabs>
   <TabItem label="Homebrew">

   macOS and Linux. On macOS 12 and earlier, where Homebrew may ask for a newer Xcode, use the installer or Cargo instead.

   ```bash
   brew install crocodile-labs/tap/openmoat
   ```

   </TabItem>
   <TabItem label="Installer">

   macOS and Linux; puts `openmoat` in `~/.cargo/bin`.

   ```bash
   curl --proto '=https' --tlsv1.2 -LsSf https://github.com/crocodile-labs/openmoat/releases/latest/download/openmoat-installer.sh | sh
   ```

   </TabItem>
   <TabItem label="Windows">

   PowerShell.

   ```powershell
   powershell -ExecutionPolicy Bypass -c "irm https://github.com/crocodile-labs/openmoat/releases/latest/download/openmoat-installer.ps1 | iex"
   ```

   </TabItem>
   <TabItem label="Cargo">

   From crates.io, with Rust 1.95.

   ```bash
   cargo install openmoat --locked
   ```

   </TabItem>
   </Tabs>

   Every install also puts a `moat` command beside `openmoat` that runs it, so hooks and scripts from older releases keep working. The `moat` name will be removed in a later release; use `openmoat`.

2. **Set it up for your agents**

   ```bash
   openmoat init
   ```

   `openmoat init` writes the default policy to `~/.moat`, then lists the agents it finds (Claude Code, Codex, Cursor, OpenClaw, GitHub Copilot CLI, pi, Gemini CLI) and asks once for each, after one line per file it would change (`d` shows the full diff; the line counts below are an example):

   ```text
   Found these agents:
     Claude Code  /Users/you/.claude (changes settings.json)
     Codex        /Users/you/.codex (changes hooks.json, config.toml)
     /Users/you/.claude/settings.json: edited, +310 -0 lines; sets env, hooks, permissions, sandbox
   Protect Claude Code (/Users/you/.claude)? [Y/n/d]
     /Users/you/.codex/hooks.json: new file, +23 -0 lines; sets hooks
     /Users/you/.codex/config.toml: edited, +12 -0 lines; sets sandbox_workspace_write
   Protect Codex (/Users/you/.codex)? [Y/n/d]
   ```

   It backs up every file before it changes it, and its last lines name the backups and `Undo anytime: openmoat uninstall`. `openmoat init --hosts claude-code,codex` skips the questions; `--dry-run` shows what would change. Run it in your own terminal: without a terminal and without `--hosts` or `--yes`, it sets up `~/.moat` but changes no agent's files.

   Nothing is added to your projects: every project you open with a protected agent is covered by this one policy ([Use it in your projects](/docs/your-projects/)).

3. **Start your agent in a new session**

   Hooks are read when a session starts, so open a new one. Then work as usual: most calls run exactly as before.

   Codex runs a new hook only after you trust it in its `/hooks` view. Restart OpenClaw's Gateway, and pi. What each agent's hook covers: [Supported agents](/docs/agents/).

4. **Check that it works**

   ```bash
   openmoat status                            # each agent: hook + OS sandbox, hook only, or not protected
   openmoat policy check "cat ~/.ssh/id_rsa"  # the verdict for a command, without running it
   ```

   ```text
   ⛔ deny
      rules : secrets-paths
      reason: secret material: read /Users/you/.ssh/id_rsa
      also  : shell "cat ~/.ssh/id_rsa"
   ```

   `openmoat status` marks each agent's line `✔ installed`, `· not set up`, `· host not found` or ``✗ hook missing (run `openmoat init`)``, then its protection, and exits 64 when something needs fixing; each fix is in [Hooks, lock and binary](/docs/troubleshooting/hooks-and-lock/#an-agent-shows-hook-only-or-not-protected).

   `openmoat demo` shows the verdict, rule and reason for a short list of example agent calls (everyday work, a private key read, a key sent out, a misspelled package, switching OpenMoat off) with your policy. Nothing runs, and no file is changed.

5. **When something is blocked**

   The agent shows the rule and the reason, for example `moat: deny [default.net] — no rule matched net docs.rs` or `moat: ask [git-internals] — …`. Find the message in [Something was blocked](/docs/blocked/) and run the command next to it in your own terminal:

   ```bash
   openmoat allow --last            # the call you were just asked about, for this agent session
   openmoat allow --site docs.rs    # a host, for good
   openmoat allow --dir ~/work/lib  # a folder outside the project, for good
   ```

   Then ask the agent to try again; after `--site` or `--dir`, start a new session so the sandbox follows. `openmoat allowed` lists what you allowed, with the command that takes each back. A deny on your keys or `.env` files is the block working: nothing to fix.

</Steps>
