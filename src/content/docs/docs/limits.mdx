## In detail

- **Cursor** runs a command outside the sandbox OpenMoat configures when its Auto-review approves it, in Run Everything mode, and in the Cursor CLI without `--sandbox enabled`; inside the workspace its sandbox cannot deny `.env` or `.git`.
- **Claude Code's sandbox** covers `Bash`, `PowerShell` and `Monitor`. File tools, `WebFetch` and MCP servers are checked by the hook only.
- **On Linux**, `moat run` does not protect files inside the project (`.env`, `.envrc`, `.moat`, `.git` hooks); `moat run --isolate` does.
- **On native Windows** only the hook applies the policy; use WSL2 for the OS sandbox.
- **A missing hook binary:** if `moat` is missing or killed, Codex and Claude Code before 2.1.295 run the call unchecked. `moat status` reports it. With Claude Code 2.1.295 or later, `moat init` sets the hook's `onFailure: "block"`, so the call is blocked.
- **Token checks see only known formats, where the hook sees them.** `token-egress` reads URLs, web searches, MCP URL arguments and command arguments. It does not see a token in a file a command uploads, a here-document, a variable not on the command line, or an encoded or split token, and tokens without a vendor prefix pass.
- **The push check reads what git shows at the time of the call.** A commit made later on the same command line, and a push through a program other than `git` and `gh`, are not seen.
- **A changed MCP server still starts.** OpenMoat refuses its tool calls, but the agent starts its servers when a session begins. `moat mcp proxy` does not pin prompts, resources or tool results, and does not cover remote servers.
- **An allowed host can front for another site on the same provider.** `moat proxy` refuses an encrypted server name (ECH or ESNI) unless `sandbox.proxy_allow_ech: true`, but it does not see the HTTP `Host` header inside the tunnel. Browsers driven through the proxy send ECH, so they are refused too.
- **The standalone `moat proxy` takes no credential.** Any local process may use it, and session taint does not apply there; `moat run`'s own proxy serves only its run.
- **Files you run later.** An agent may edit `package.json` scripts, a `Makefile` or other build files without a question; they run when you next build. CI workflows, commit-hook files, and the agent hooks and MCP settings its host starts next session ask first (`runs-later`), but only for the agent's own writes: a script the agent runs in its sandbox may still write them.
- **Folders allowed with `moat allow` before 0.5.2** do not leave out `.git` and the files run later: add them again ([Work across several repos](/docs/work-across-repos/)).

The full list, with the reasons: [THREAT_MODEL.md](https://github.com/crocodile-labs/openmoat/blob/main/docs/THREAT_MODEL.md). What each layer stops is tested on every change: [EVIDENCE.md](https://github.com/crocodile-labs/openmoat/blob/main/docs/EVIDENCE.md).
