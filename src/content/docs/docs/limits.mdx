OpenMoat checks the tool calls an agent's hook reports. It does not confine every call, and it does not replace your agent's prompt or sandbox. These are the gaps that remain.

## The main gaps

- **A deferred call runs if your agent lets it.** In auto-approve modes (`--dangerously-skip-permissions`, Run Everything) only `deny` and `review` stop a call.
- **Outside an OS sandbox, the hook decides alone.** For hook-only agents (OpenClaw, GitHub Copilot CLI, pi, Gemini CLI, OpenCode, Hermes Agent, the Cline CLI, goose, and Claude Code and Cursor on native Windows), an allowed call runs with your permissions, so a classifier mistake is a way past OpenMoat. Claude Code's sandbox covers only `Bash`, `PowerShell` and `Monitor`; its file tools, `WebFetch` and MCP servers run outside it. Cursor runs some commands outside its sandbox.
- **Under `openmoat run`, the agent's own login is readable to the commands it runs.** Since 0.16.0 every OS sandbox denies the agents' login and key files (`agent-credentials`) to the commands an agent runs; Claude Code's, Codex's and Cursor's sandboxes confine only those commands, so the agent still signs in. `openmoat run` holds the agent itself, so it keeps that agent's own login readable, and code inside an allowed command can read it there; other agents' logins stay denied. An API-key login can go through the broker instead; an OAuth login cannot ([ADR-054](https://github.com/crocodile-labs/openmoat/blob/main/docs/adr/ADR-054-agent-credentials-in-sandboxes.md)). On a hook-only agent, the hook is the only check.
- **Allowed scripts and hosts.** An allowed `npm test` runs whatever it contains; the sandbox bounds it, OpenMoat does not inspect it. Without a sandbox, a script the session wrote needs review before an interpreter runs it ([Code the agent wrote](/docs/session-written-code/)), but a test runner, build tool or package script (`pytest`, `npm test`, `cargo test`, `make`) running files the session wrote does not, nor does a file another session wrote or one written by a program whose writes the hook cannot see (the files `tar x` or `unzip` extract, a build's or a package manager's output, what a script writes). An allowed host can receive data from an allowed command: the proxy checks the host, not what is sent inside HTTPS.
- **Tools no hook exposes are not seen**, such as Codex web search and hosted tools, and the shell commands you type yourself in OpenCode (`!`).
- **A repository's git configuration runs before any hook.** A `.git/config` that names a program (`core.fsmonitor`, a pager, a filter) runs when the editor's or the agent's own background git starts; `openmoat status` and `openmoat doctor` name such keys but cannot stop them. In the editors, the selection and open file Claude Code adds to a prompt are no tool call and are not checked ([Editors](/docs/editors/#limits)).
- **Some agents run a call when the hook fails.** Codex, and Claude Code before 2.1.295, run a call unchecked if `openmoat` is missing. GitHub Copilot CLI and Gemini CLI run a call whose hook times out. OpenClaw, pi and OpenCode run calls unchecked when they do not load OpenMoat's plugin or extension (OpenCode 1 with `--pure` or `OPENCODE_PURE`, OpenCode 2 with `-openmoat` in a project's `plugins`, or when the plugin fails to load, which each of them logs and goes on; `openmoat status` reports such a project). The plugin reports loading, and `openmoat status` says "plugin not loaded yet" until it has, and for pi "not protected" once pi ran without it ([Plugin loading](/docs/agents/plugin-loading/)). Hermes Agent's gateway, cron and ACP sessions skip the hook when its command is not approved in `shell-hooks-allowlist.json` (`openmoat init` approves it), as Hermes does under `HERMES_SAFE_MODE=1` or in a profile OpenMoat did not set up, and Hermes runs a call unchecked when its own hook dispatcher fails (a Hermes bug, not a failing hook). The Cline CLI runs a call whose hook script cannot start (no `sh`), prints something that is not JSON or is killed after 120 seconds; OpenMoat's script itself blocks the call when `openmoat` is missing or gives no answer. goose runs every call unchecked when it does not load OpenMoat's plugin.
- **Other plugins share the agent's process.** OpenCode loads other plugins and a project's `.opencode/plugins/` at start, with no prompt, and they can change what OpenMoat's plugin does; `openmoat status` and `openmoat doctor` warn about a project's. A plugin that rewrites a call OpenMoat checked makes that call fail, but one can still replace a tool, rename one, or change a shell's directory or environment.
- **Some agents can change a call after the check.** Hermes Agent's plugins, another of its shell hooks and its tool middleware run in its own process and can rewrite a call's arguments after OpenMoat decided; what an `execute_code` script does itself is not checked, and its in-session `/yolo` toggle approves a review unseen. A pi extension that loads after OpenMoat's can change a call's input. OpenClaw runs the parameters OpenMoat decided on, except where another plugin changes them and asks for approval itself in one answer: OpenClaw then runs that plugin's change once you approve it ([OpenClaw](/docs/agents/openclaw/)).
- **Some agents cannot prompt.** Codex, OpenCode 1, goose, the Cline CLI (where the deny also ends Cline's run), Cursor's file tools, pi in print and JSON mode, and Hermes Agent in YOLO mode receive a `review` as a deny (a block, in goose) that says how to approve the call (`openmoat`, or `openmoat allow --last`); GitHub Copilot CLI in autopilot turns it into a deny itself.
- **OpenCode 2's `--auto` approves OpenMoat's reviews** as it approves OpenCode's own, and OpenMoat's plugin cannot tell. OpenCode before 1.3.4 is not supported: `openmoat init` does not set it up and `openmoat status` says to upgrade.
- **Agent settings can turn hooks off.** Codex runs a new or changed hook only once you trust it in its `/hooks` view, and settings such as `disableAllHooks` (Claude Code, Copilot CLI) or `[features] hooks = false` (Codex) turn hooks off. `openmoat status` and `openmoat doctor` report the settings they can see.
- **A program that runs as you outside any sandbox** can change the policy and recompute the lock. Only the OS sandboxes stop that, so hook-only agents do not have this protection.
- **On Linux, plain `openmoat run` does not protect files inside the project** (`.env`, `.git`, `.moat`); `openmoat run --isolate` does. Plain `openmoat run` says so when it starts, and `openmoat doctor` warns.

## Limits of single checks

- **Injected input is linked only with Claude Code, the Cline CLI and wrapped MCP servers, and only for the same request.** Other agents report no call output (their wrapped MCP servers' results are read by the gateway). Another spelling of a planted address, a subdomain of a planted URL host and a planted command run through a wrapper are linked; a host by another name, a reworded command or a relative path is not. Only the output of `Bash`, `WebFetch`, `WebSearch`, MCP resource reads and MCP tools is read, each kept up to fixed bounds, so a page full of decoys can push a planted host out. Fetches, searches and MCP calls themselves are not checked against it, and an install without the `PostToolUse` entry (`openmoat init` adds it) links nothing ([Injected input](/docs/injected-input/)).
- **Sending what a session collected is recorded, not stopped.** A send after the session read many files outside the project, or packed them into an archive or an encoding, carries `@staging-egress` in the audit log and in `openmoat report`, but no default rule decides it yet. Only reads that went through OpenMoat's hook are counted (ADR-061, proposed).
- **The container check reads the flags as written.** `container-host` matches the options a `docker`, `podman` or `nerdctl` command line shows; another spelling, or the same options in a compose file or a script, is not caught by it ([Code that runs later](/docs/runs-later/)).
- **The MCP flow check sees wrapped servers and exact text only.** Results of a server not run through `openmoat mcp wrap` (remote HTTP, plugin or managed servers) are not recorded, and text the agent rewrites, encodes, splits or shortens below eight words is not found; a tool's own annotations or its name decide whether it writes or sends ([MCP data between servers](/docs/mcp-servers/cross-server/)).
- **The card check is narrow and can misfire.** `card-egress` reads only the text a call shows: a number in a file (`curl -d @cards.csv`), encoded or split is not seen. `openmoat allow` cannot lift a deny: narrow or remove the rule with `openmoat edit` ([Card numbers sent out](/docs/env-files/card-numbers/)).
- **The pull request check reads added lines, not programs.** It matches the text a change adds (and the lockfile lines it removes), offline: a payload built from pieces at run time, a script the change does not touch and a package's age or owner are not checked, and a benign line can match (set its level in `check_diff.levels`). A finding is a report: it holds a merge only where the job is a required status check ([Check a pull request](/docs/check-a-pull-request/#limits)).
- **Provenance notes are local evidence of what the hook saw.** A script, an editor or an agent without OpenMoat leaves no record. Notes are not signed and can be stripped or left unpushed: a missing note proves nothing, and only the machine that wrote a note can verify it; in CI it is a claim ([Provenance](/docs/see-what-happened/provenance/#limits)).

## Per agent

- **Gemini CLI** runs no hooks in a folder it does not trust (it asks you before every tool there instead). A project's `.gemini/settings.json` can turn hooks off or add a hook that rewrites a call's arguments, and extension hooks run beside OpenMoat's; `openmoat status` and `openmoat doctor` warn about such a project file.
- **pi** has no approval step of its own, so a call OpenMoat defers runs without a question. A trusted project's `.pi` settings and extensions load with the agent's rights.
- **GitHub Copilot CLI** tells MCP tools apart from built-in ones only by name, so a changed server is traced by its `<server>-` prefix. Its shells keep their working directory between calls while the payload names only the session's, so after you approve a `cd` out of the project a later relative path is still checked against the session's directory.
- **Hermes Agent** sends the Hermes process's directory, not the session's: a relative path is checked against the directory Hermes started in, and one that climbs out (`..`) or a `terminal` call that moves the shell outside it needs review. Terminal commands on a remote backend (docker, ssh, modal, …) are checked as local ones. A changed `config.yaml` is caught on the next call, not when it is written.
- **OpenClaw**: process input to a running `exec` session and Code Mode `exec` are left to OpenClaw, and `code_execution` runs at the model provider. A cron job added or updated needs review; what the job will do is not checked. A plugin registered at the same lowest priority after OpenMoat's, or at a lower one, runs after it.
- **OpenCode**: a plugin can still replace a tool's implementation, advertise a tool under another name, or change a shell's working directory or environment. `task` and `subagent` calls are hooks of their own with their own session id, so taint and grants do not follow the parent session.
- **Codex's `workdir` and Cursor's `cwd` are the model's choice**, so a command run from outside the session's project is decided as running in the session's directory; Codex's own sandbox still applies where the command runs. Codex types later input into a running shell or REPL with `write_stdin`, which runs no hook, so starting a bare shell, REPL, editor or login (`bash`, `python3`, `ssh host`) needs review.
- **The Continue CLI** runs no hooks yet: OpenMoat cannot check its calls. Use `openmoat run`.

## In detail

- **Code the session wrote is checked only as far as the hook sees it.** Where no OS sandbox from OpenMoat holds the command, running a file the same session wrote needs review, and so does inline code that builds the names of the files it opens (`opaque-code`). Not covered: test runners, build tools and package scripts; files another session or a person wrote; the member files of an archive, a build's or a package manager's output, what a script the agent wrote writes in turn, a download saved under a name the command does not show; code a program loads on its own (`import helper`, `require('./lib')`, a `conftest.py`, a git hook); a program named through a variable whose value the line does not show; PowerShell and `cmd`; inline code whose built text the scan does not recognise as built. A flag that turns a sandbox off when the agent starts (Codex's `--sandbox danger-full-access`) is not seen. The record of what each session wrote keeps 30 days and the newest 100 000 files.
- **Agent logins outside the sandboxes.** `agent-credentials` denies the agent's own tools reading or writing them, and every OS sandbox denies them to the commands an agent runs (from 0.16.0), except the started agent's own login under `openmoat run`. Any program an allowed command runs on a hook-only agent can still read them (ADR-054). A recursive read of the folder that holds them needs review (`protected-contents`), and once you approve it the copy holds the files. The Maven and Gradle settings `build-credentials` names, and the agents' system-wide settings `managed-settings` names, are denied by the hook only.
- **An agent's own process is not checked.** A flaw inside the agent itself runs where no hook sees it. OpenMoat holds for review the agent running its own CLI to save an MCP server or start an MCP sign-in (`runs-later`), and `openmoat status` and `openmoat doctor` warn when the installed version has a published advisory with a fixed version; that list is only as current as the OpenMoat release.
- **Cursor** runs a command outside the sandbox OpenMoat configures when its Auto-review approves it, in Run Everything mode, and in the Cursor CLI without `--sandbox enabled`; inside the workspace its sandbox cannot deny `.env` or `.git`.
- **Claude Code's sandbox** covers `Bash`, `PowerShell` and `Monitor`. File tools, `WebFetch` and MCP servers are checked by the hook only.
- **On Linux**, `openmoat run` does not protect files inside the project (`.env`, `.envrc`, `.moat`, `.git` hooks); `openmoat run --isolate` does. Where bubblewrap is missing or cannot create user namespaces, `openmoat run` restricts the network by port only, so a command could connect to another host on the proxy's port; it says so on every start, and `openmoat doctor` warns.
- **On Linux without a network namespace**, `openmoat run` refuses a `--write` path that holds what `kernel-self` protects (`--write ~/.claude` holds `settings.json`). Install bubblewrap and allow unprivileged user namespaces.
- **Inside `openmoat run`**, commands cannot write an agent's own configuration in the project (`.claude/hooks/`, `.mcp.json`, `.github/hooks/`, `.pi/…`, OpenCode's `opencode.json[c]` and `.opencode/…`, and the like) on macOS, even when you allowed the write; on Linux only the files existing directly in the project are protected that way, and only where the agent gets a network namespace. Change those files outside `openmoat run`. Programs that open a new terminal inside (`script`, `expect`, `node-pty`) can fail, and on Linux containers and Chromium's own sandbox do not start.
- **On macOS 12 and earlier**, `openmoat run` does not start; the hooks still apply the policy.
- **On native Windows** the hook applies the policy, and only Codex has an OS sandbox; use WSL2 for the others. `openmoat run` and `openmoat proxy install` are not available, and PowerShell commands are not parsed, so OpenMoat never allows one.
- **Project settings loaded at session start.** A repository's `.claude/settings.json` can turn Claude Code's hooks off with `disableAllHooks`, and Claude Code loads it before any hook runs. OpenMoat blocks such a change made during a session and `openmoat doctor` warns, but only Claude Code's managed settings stop it at start ([Keep Claude Code's hooks on for everyone](/docs/team-rules/#keep-claude-codes-hooks-on-for-everyone)).
- **A missing hook binary:** if `openmoat` is missing or killed, Codex and Claude Code before 2.1.295 run the call unchecked. `openmoat status` reports it. With Claude Code 2.1.295 or later, `openmoat init` sets the hook's `onFailure: "block"`, so the call is blocked. Cursor, OpenClaw, GitHub Copilot CLI, pi, Gemini CLI, OpenCode, Hermes Agent and goose block it too, and for the Cline CLI OpenMoat's hook script blocks it.
- **Token checks see only known formats, where the hook sees them.** `token-egress` reads URLs, web searches, MCP URL arguments and command arguments. It does not see a token in a file a command uploads, a here-document, a variable not on the command line, or an encoded or split token, and tokens without a vendor prefix pass.
- **The push check reads what git shows at the time of the call.** A commit made later on the same command line, and a push through a program other than `git` and `gh`, are not seen.
- **A changed MCP server still starts.** OpenMoat refuses its tool calls, but the agent starts its servers when a session begins. `openmoat mcp proxy` does not pin prompts, resources or tool results, and does not cover remote servers; as the gateway it covers stdio servers only, and tool results reach the model as the server sent them ([The MCP gateway](/docs/mcp-servers/gateway/)).
- **A browser goes where the page sends it.** A browser MCP call that only opens a page defers like `WebFetch`; where the page's scripts, links and redirects lead, the hook cannot see ([Browser page opens](/docs/mcp-servers/browser-pages/)).
- **Ports count in the proxy, not in the hook.** Through `openmoat proxy` and `openmoat run`, an allowed host is reached on ports 443 and 80 only unless a rule names `host:port`. The hook decides by host alone, so for a hook-only agent an allowed command connects to any port of an allowed host.
- **A plain download from an unlisted host defers.** A `curl` or `wget` that sends nothing but its URL goes to your agent's prompt, like a web fetch, and the file it saves is checked by the path rules. The hook cannot see a host name that resolves to an internal address, curl's configuration file next to its binary on Windows, or a proxy variable set before the session (writing `~/.curlrc` or `~/.wgetrc` is denied by `shell-rc`, moving them by `env-poison`); under `openmoat run` and the agents' sandboxes the proxy still refuses link-local and metadata addresses.
- **An allowed host can front for another site on the same provider.** `openmoat proxy` refuses an encrypted server name (ECH or ESNI) unless `sandbox.proxy_allow_ech: true`, but it does not see the HTTP `Host` header inside the tunnel. Browsers driven through the proxy send ECH, so they are refused too.
- **Only Claude Code's sessions get a credential for the standalone `openmoat proxy`.** It serves agent sessions only, but Codex's proxy sends no credential, so its traffic is refused unless `sandbox.proxy_serve_without_credential: true` serves it, with no session and no taint; Cursor's sandboxed commands never reach it. A credential is shared by everything in its session ([Agent sessions only](/docs/egress-proxy/sessions/)).
- **HTTPS is decrypted only inside `openmoat run`, for a `tls: terminate` secret's host.** A client that ignores `SSL_CERT_FILE` and `NODE_EXTRA_CA_CERTS`, or speaks only HTTP/2, cannot reach that host there; elsewhere an HTTPS request keeps the placeholder ([Secrets over HTTPS](/docs/keep-tokens-safe/https-injection/)).
- **Files you run later.** An agent may edit `package.json` scripts, a `Makefile` or other build files without a question; they run when you next build. CI workflows, commit-hook files (in `.git/hooks` and folders such as `.githooks/`), Cline's workspace hooks, the agent hooks and MCP settings its host starts next session, the editors' project configuration, virtual environments' `bin/`, dev container configuration, package-manager configuration that runs code, and the `.pth`, `sitecustomize.py` and `usercustomize.py` files every Python start runs, need review first (`runs-later`), but only for the agent's own writes: a script the agent runs in its sandbox may still write them ([Code that runs later](/docs/runs-later/)).
- **File taint follows direct reads only.** A file a tainted session wrote taints the session that reads or runs it, but not when it is copied or renamed, not the files a build or a script writes, and not files a search tool reads.
- **Interpreter code is scanned, not parsed.** Environment reads are recognised by their usual spellings; the environment reached through an alias (`e = os.environ`, then `print(e)`), a command built at run time, or another spelling is not seen.
- **Package checks go by the name, offline.** `package-near-miss` holds for review only a name close to one on a bundled list of popular packages; it does not see a squat on a name off the list, short names, lockfile installs, dependencies, `npx`, or a compromised popular package. The 7-day release age covers npm and uv inside `openmoat run` only, and a program that resets the variables escapes it.
- **The audit log can be cut short by whoever can write it.** Deleting its newest events leaves a log that still checks out. `openmoat audit verify --against` catches it only for events up to your last anchor, and only if the anchor is kept where that person cannot rewrite it.
- **On Linux, `openmoat run` refuses to start when `MOAT_HOME` sits inside a folder the sandbox grants** (under `/tmp`, say), since the sandbox could not hide OpenMoat's state there. The message names the folder to move it out of.
- **A policy signature proves who signed, not that the rules are good.** A stolen signing key signs packs you will install.
- **Folders allowed with `moat allow` before 0.5.2** do not leave out `.git` and the files run later: add them again ([Work across several repos](/docs/work-across-repos/)).

The full list, with the reasons: [THREAT_MODEL.md](https://github.com/crocodile-labs/openmoat/blob/main/docs/THREAT_MODEL.md#5-known-limitations). What each layer stops is tested on every change: [EVIDENCE.md](https://github.com/crocodile-labs/openmoat/blob/main/docs/EVIDENCE.md).
