<Aside type="note" title="Read this when">

You want to know what an agent ran, what was blocked, or whether OpenMoat is getting in your way.

</Aside>

**Protects against** not knowing what an agent did, and a record of it being changed afterwards without anyone noticing.

## What it does

Every decision (allow, defer, ask, deny), every connection `openmoat proxy` decides and every tool call through `openmoat mcp proxy` goes into a local SQLite file in `~/.moat`, each event hash-chained to the one before. Credentials are redacted before anything is stored. The agent can neither read nor change it (`kernel-self`).

## Example

### Today at a glance

```bash
openmoat
```

```text
Protecting Claude Code (hook + OS sandbox) · today: 14 decisions, 1 denied, 1 asked
Claude Code asked to run "git config core.pager less" (rule git-internals, session 4f2a…)
Allow? [o]nce for this session / [a]lways / [n]o
```

It shows what needs you first. When nothing does, it says `Nothing needs you.`

## The latest decisions

```bash
openmoat show                 # recent events
openmoat show 1               # one event in full
openmoat show --since today   # a time window: today, yesterday, 3h, 7d, 2026-10-15
```

```text
id     time (UTC) host         verdict rules          action
2      09:12:04   claude-code  defer   default        npm install left-pad
1      09:12:03   claude-code  deny    secrets-paths  cat ~/.ssh/id_rsa
```

## One session as a timeline

```bash
openmoat replay --since today
```

One tree per agent session: every call, its verdict and the rule that decided it.

## A report

```bash
openmoat report --since 7d
```

Totals, the hosts the agents reached, the rules that fired most, and asks per active hour. If you are asked often, this shows which rule does it, so you know what to allow.

## Export and verify

```bash
openmoat audit export --since 7d > week.jsonl   # events as JSON Lines, with their chain hashes
openmoat audit verify week.jsonl                # check it was not changed, without the database
```

For a team, collect each person's export and run one report over all of them. Every file must verify first, and an event found in several files counts once:

```bash
openmoat audit report alice.jsonl bob.jsonl     # per agent, per rule, top asks and denies
```

## Keep a record outside the log

Every event is hash-chained to the one before, so a change in the middle of the log shows. But someone who can write the log file can delete its newest events and leave a shorter log that still checks out. To catch that later, record the log's head somewhere else now and then:

```bash
openmoat audit anchor --git ~/notes            # a commit on refs/moat/anchors in that repository
openmoat audit anchor --file ~/anchors.jsonl   # or one line appended to a file you keep
openmoat audit verify --against ~/notes        # later: check today's log against every anchor
```

An anchor holds the newest event's id, its hash and the time. Nothing is pushed or sent anywhere: an anchor is only as safe as where you keep it, so push the ref (`git -C ~/notes push origin refs/moat/anchors`) or copy the file to another machine.

`openmoat audit verify --against` fails when an anchored event was deleted or rewritten, and names the first such anchor. Events after the newest anchor are not covered. `openmoat doctor` shows when you last anchored. The agent cannot run `openmoat audit anchor` (`kernel-self`).

<Aside type="tip" title="Private by design">

The log is a SQLite file in `~/.moat`. Credentials are redacted before anything is stored, and nothing leaves your machine unless you export or anchor it somewhere that does. The agent's own reads and writes of the log file are denied (`kernel-self`).

</Aside>

## Commands

| Command | What it does | Example |
|---|---|---|
| `openmoat` | One line of today's decisions, then anything that needs you | `openmoat` |
| `openmoat show [id] [--session <id>] [--since <when>] [--recent N]` | Recent events, one session, or one event in full | `openmoat show --since today` |
| `openmoat replay [--since <when>] [--session <id>]` | Each agent session as a tree of calls, verdicts and rules | `openmoat replay --since today` |
| `openmoat report [--since <when>] [--host <id>]` | Totals, hosts reached, top rules, asks per active hour | `openmoat report --since 7d` |
| `openmoat audit export [--since …] [--host …] [--session …]` | Events as JSON Lines, with their chain hashes | `openmoat audit export --since 7d > week.jsonl` |
| `openmoat audit verify <file> [--anchor <hash>] [--require-anchor]` | Check an export without the database | `openmoat audit verify week.jsonl` |
| `openmoat audit verify --against <repo or file>` | Check the log against every anchor recorded there | `openmoat audit verify --against ~/notes` |
| `openmoat audit anchor --git <repo>` · `--file <path>` | Record the log's head outside it. Terminal only | `openmoat audit anchor --git ~/notes` |
| `openmoat audit report <file>…` | One report over verified exports from several machines | `openmoat audit report alice.jsonl bob.jsonl` |

`--since` takes `all`, `today`, `yesterday`, `12h`, `7d`, `2w` or a date (`2026-10-15`, UTC). Most commands take `--format json`.

## Settings

None: every decision is recorded. Where you keep anchors is up to you ([above](#keep-a-record-outside-the-log)).

## Limits

- **Tamper-evident, not tamper-proof.** Whoever can write the log file can delete its newest events and leave a log that still checks out; `openmoat audit verify --against` catches that only up to your last anchor.
- **Only what the hooks and the proxy see is recorded.** A call a hook never reports (Codex web search, hosted tools) is not in the log.

More in [Limits](/docs/limits/).
