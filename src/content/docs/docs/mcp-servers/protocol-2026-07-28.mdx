**Protects against** a server that steers the model through a sampling request, sends you to a page on your own network or the cloud metadata address, slips an argument into an HTTP header, or changes what it is by publishing a new package release under the same name.

## Both protocol revisions

- **What is pinned under 2026-07-28:** the server's `server/discover` answer (its instructions, capabilities and versions; the cache hints `ttlMs` and `cacheScope` are not pinned) and the server information each result names.
- **A server whose results name another server** than the one you accepted is held: all its calls are refused until `openmoat mcp accept`. A new version number alone holds nothing.
- **A server you accepted under the older revision** keeps its acceptance while its text stays the same.

## What a server asks of you

| Request | What the gateway does |
|---|---|
| Sampling (`sampling/createMessage`: the server asks the model to write text), as a request or inside a 2026-07-28 result's `inputRequests` | refused, since the server would choose text the model reads as a user turn; passed with `mcp: { allow_sampling: true }`. One that asks for the session's context is refused either way |
| URL elicitation (the server asks the agent to open a page for you) | passed only for an `https` page on a host that is not this machine, a private network or a link-local address such as `169.254.169.254`, and that a `net` rule of your policy does not deny |

A refused request refuses the whole answer, with error -32001.

```yaml
mcp:
  allow_sampling: true    # optional, default false
```

## Where an argument goes

A 2026-07-28 tool can send an argument as an HTTP header (`x-mcp-header`). `openmoat mcp accept` names each such mapping, and a changed one holds the tool. A tool whose mappings break the specification's rules, or whose schema's `$ref`s point outside it, loop or nest too deep, is left out and its calls refused.

## Package releases

When you accept a server started with `npx`, `uvx` or `docker run`, OpenMoat records the release it runs, read from the command line and the package manager's own files on this machine. No network is used. A new release changes the definition: its tool calls are refused, and a wrapped server does not start, until you accept it again with `openmoat mcp accept <server>`. This covers wrapped and unwrapped stdio servers.

## Limits

- **Stdio servers only.** A remote (HTTP) server, plugin servers and managed MCP configuration are checked by the hook alone.
- **Releases are read offline.** A runner OpenMoat does not read (`bunx`, `pnpm dlx`, a global install, a `node` path), an image tag without a digest, or a cleared cache records nothing or only a tag. A release the package manager installs as the server starts is seen on the next check, after that start.
- **2026-07-28 retries need their own hook decision.** A `tools/call` that answers a server's `input_required` result is a new call to the gateway; an agent that does not run its hook for the retry gets it refused.
- **Self-referring schemas are refused**: a tool whose schema refers to itself (a recursive tree type) or to another document.
