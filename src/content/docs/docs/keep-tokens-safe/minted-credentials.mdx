**New in 0.27.0, preview.** GitHub, AWS and Google Cloud each have an official call that turns a credential you hold into a narrower one that expires on its own. A `mint` source makes the proxy of `openmoat run` (or `openmoat proxy`) make that call itself, outside every sandbox, and broker the result like any other [brokered secret](/docs/keep-tokens-safe/), renewed before it ends. Your own credential is read by the proxy only, each time it mints, and sent only to the provider's own endpoint.

Minted credentials need `openmoat run`. **A normal `gh` login cannot be narrowed**: GitHub has no call that narrows an OAuth or personal access token such as the one `gh auth token` prints, so a GitHub mint starts from a GitHub App you create and install on the repositories you choose.

## How to use it: git for an agent, as a GitHub App, one repository

1. On GitHub, create a GitHub App (Settings → Developer settings → GitHub Apps → New): no webhook, repository permission **Contents: Read and write**. Note its **Client ID**.
2. On the App's page, **Install App** on your account, choosing **Only select repositories** and the one repository. The installation's page URL ends in its **installation ID**.
3. On the App's page, **Generate a private key**, and move the downloaded `.pem` to `~/.config/moat/app.pem`.
4. In your own terminal, run `openmoat edit` and add the `gh-git` entry from the example below (your Client ID, installation ID and repository name) and the `mint-credentials` deny rule.
5. Start the agent under OpenMoat's sandbox: `openmoat run -- claude` (or any agent). Inside it, `git push` and `git pull` to that repository work with a token that lasts an hour and reaches that repository alone; the agent never sees the key.
6. To stop: remove the entry with `openmoat edit`, and uninstall the App on GitHub.

## Example

```yaml
secrets:
  # git push and pull to two repositories, as a GitHub App, for an hour at a time.
  - id: gh-git
    host: github.com
    header: Authorization
    helper: { git: { username: x-access-token } }
    source:
      mint:
        github-app:
          app: Iv23liExample              # the App's client ID (or numeric App ID)
          installation: 12345678          # the installation on your account or organisation
          key: ~/.config/moat/app.pem     # the App's private key
          repositories: [openmoat, site]  # names, without the account or organisation
          permissions: { contents: write, pull_requests: read }

  # Reading one bucket, for 15 minutes at a time.
  - id: s3
    host: s3.us-east-1.amazonaws.com
    header: Authorization
    helper: aws
    source:
      mint:
        aws-sts:
          role: arn:aws:iam::123456789012:role/agent
          region: us-east-1
          profile: work                   # of ~/.aws/credentials; `default` when unset
          actions: [s3:GetObject, s3:ListBucket]
          resources: ["arn:aws:s3:::example-bucket", "arn:aws:s3:::example-bucket/*"]
          lifetime: 15m                   # 15m to 12h

deny:
  - id: mint-credentials                  # the agent must not read what the proxy mints from
    fs.read: ["~/.config/moat/app.pem"]
```

Then:

```bash
openmoat edit                    # add the secrets and the deny rule
openmoat policy lint             # warns when no deny rule covers the file a mint starts from
openmoat run -- claude           # the run's proxy mints; git and aws inside get the values
```

The default `secrets-paths` rule already denies `~/.aws` and `~/.config/gcloud`; a GitHub App's key needs a rule of your own, as above.

## What it mints

| Provider | What it mints | Narrowed to | Lifetime | Starts from |
|---|---|---|---|---|
| `github-app` | an installation access token | `repositories` and `permissions`, both required | 1 hour (GitHub's) | the App's private key |
| `aws-sts` | STS `AssumeRole` credentials | an inline session policy: `actions` on `resources`, both required; never `s3:*` or `*` | 15m to 12h, 15m by default | a profile of `~/.aws/credentials` |
| `gcp` | a service account access token | `scopes`, required | 1m to 1h, 15m by default | your Google Cloud application default credentials, or a service account key |

- **A mint that would not narrow does not load.** Without `repositories` a GitHub token reaches every repository of the installation; without a session policy an AWS session has all of the role. A GitHub answer that grants a permission the entry does not ask for is refused.
- **Renewal:** before the value ends (10 minutes ahead for GitHub, a fifth of the lifetime for the others), retried every 15 seconds on failure. A request that would get an expired value is refused (`proxy-secret-expired`).
- **Errors** name the provider, its HTTP status and its error code, never a value.

## git and the AWS tools: `helper:`

git over HTTPS keeps its credential inside a tunnel the proxy does not open, and the AWS tools sign each request with the secret key, so there is no header the proxy could fill in. A secret with `helper:` reaches the tool through its own helper protocol, inside `openmoat run`, which sets both up:

- **`helper: { git: { username: … } }`:** git asks `openmoat credential git <id>` for that host; your own git helpers for the host are dropped for the run. The proxy answers only for the secret's own host.
- **`helper: aws`:** the run gives the AWS tools a config file of its own whose profile `openmoat-<id>` runs `openmoat credential aws <id>` as its `credential_process`, and removes `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and the like from the environment.
- **Who is answered:** only the session's own processes, through the run's proxy on loopback. Each answer, given or refused, is a row in the audit log with rule `proxy-helper`.

## Limits

- **Preview.** The format and the checks can still change.
- **Needs `openmoat run`** (or `openmoat proxy`). `openmoat guard` never mints, audit delivery refuses a `mint` source, and Claude Code's broker is never given one.
- **A value handed to a helper is readable by the session's commands.** Any command the agent runs can start `openmoat credential` as git does and print the value, as it could read a token in a variable. What bounds it: it is narrowed, ends within minutes, and goes only where the policy lets the agent connect. Use `helper:` for minted values, and keep the hosts the agent may reach few.
- **The agent's own login stays readable to its child commands.** Minting narrows the credentials you broker, not the agent's own sign-in.
- **GitHub OAuth and personal access tokens cannot be narrowed**, so OpenMoat does not mint from them.
- **`openmoat guard`'s audit rows do not mask a minted value**, as for a [`command` source](/docs/keep-tokens-safe/short-lived-tokens/#limits): only the proxy has it. The proxy's own rows mask every value it gave.
