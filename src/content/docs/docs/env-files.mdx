<Aside type="note" title="Read this when">

Your project uses .env files, or secrets live in environment variables.

</Aside>

**Protects against** the agent reading your keys, credential files, `.env` files and secret environment variables, and so against it sending them anywhere.

## What it does

`secrets-paths` denies reading and writing key and credential files (`~/.ssh`, `~/.aws`, `~/.config/gh`, `~/.kube`, `~/.npmrc`, `.env`, `.envrc`, keychains and more) and the commands that print a stored token (`gh auth token`, `aws configure export-credentials`, `kubectl config view --raw`, …). `env-secrets` denies reading a variable whose name looks like a secret, and `env-dump` denies printing the whole environment. The hook checks the agent's file tools, shell commands and MCP arguments; the agents' OS sandboxes carry the same denies, so a script the agent runs cannot read them either.

## Example

```bash
openmoat policy check "cat ~/.ssh/id_rsa"
```

```text
⛔ deny
   rules : secrets-paths
   reason: secret material: read /Users/you/.ssh/id_rsa
   also  : shell "cat ~/.ssh/id_rsa"
```

`cat .env`, `source .env`, `cat .e*`, `cat .en?` and `cat .{env,x}` are denied by `secrets-paths` the same way ([Shell command checks](/docs/shell-commands/)).

## What is denied

| The agent tries | Answer |
|---|---|
| `cat .env`, `source .env`, `cat .env.test`, `cat config/.env.local` | deny: `secrets-paths` (any `.env` or `.env.*`, at any depth) |
| `cat .envrc` | deny |
| `cat .env.example`, `.env.sample`, `.env.template`, `.env.dist`, `.env.test.example` | allow: committed templates carry no values |
| `echo $OPENAI_API_KEY`, `$GITHUB_TOKEN`, `$AWS_SECRET_ACCESS_KEY` | deny: `env-secrets` |
| `printenv`, `env`, `export -p`, `cat /proc/self/environ` | deny: `env-dump` |
| `python -c "import os; print(os.environ['GITHUB_TOKEN'])"`, `node -e "console.log(process.env.GITHUB_TOKEN)"` | deny: `env-secrets`, a read of that variable |
| `python -c "import os; print(os.environ)"`, `python3 -c 'print(__import__("os").environ)'` | deny: `env-dump`, the whole environment |
| `echo $SENTRY_URL` | **defer**: the name does not look like a secret |

Variable names that are denied: anything ending in `_KEY`, `_TOKEN`, `_SECRET`, `_PASSWORD`, `_PASS`, `_PASSWD`, `_PWD`, `_CREDENTIALS` or `_DSN`, anything starting with `AWS_`, the connection strings `DATABASE_URL`, `*_DATABASE_URL`, `REDIS_URL`, `MONGODB_URI` and `MONGO_URL`, and `GITHUB_TOKEN`, `NPM_TOKEN`, `PGPASSWORD`. Other `*_URL` variables are not.

Inline code run with `python -c`, `node -e`, `ruby -e`, `perl -e`, `php -r` and similar is read too: a variable it reads by name is checked like `echo $NAME`, and code that prints the whole environment, or reads a variable whose name is chosen at run time, is denied by `env-dump`.

## Agent logins and the folders around secrets

- **Every supported agent's login, provider keys and OAuth tokens** are denied to the agent's tools by `agent-credentials`: [Agent logins and keys](/docs/env-files/agent-credentials/).
- **A folder that holds denied files** (`cp -r ~/.codex x`, `tar czf a.tgz ~/.hermes`) asks, with `protected-contents`: [Folders that hold denied files](/docs/env-files/protected-contents/).

## Commands

| Command | Example |
|---|---|
| `openmoat policy check "<command>"`: is it denied? | `openmoat policy check 'echo $SENTRY_URL'` |
| `openmoat policy check "<path>" --kind fs-read`: a file tool's read | `openmoat policy check "~/.aws/credentials" --kind fs-read` |
| `openmoat secret add`: give the agent a token it cannot read | `openmoat secret add gh` ([Token broker](/docs/keep-tokens-safe/)) |
| `openmoat edit`: deny a file or variable of your own | see below |

## Settings

### Protect a variable with another name

Some variables hold a password although their names do not say so, such as `SENTRY_URL` or `AMQP_URL`. Deny them yourself with `openmoat edit`:

```yaml
deny:
  - id: my-secret-vars
    reason: these hold credentials
    env.read: ["SENTRY_URL", "AMQP_URL"]
```

A file is denied the same way, with `fs.read` (and `fs.write`) patterns:

```yaml
deny:
  - id: example-token
    reason: brokered secret source
    fs.read: ["~/.config/example/token"]
```

## Limits

### What this means for your tests

<Aside type="caution" title="Programs the agent starts cannot read .env either">

The agent's OS sandbox is built from the same policy, so `npm test` or `pytest` started by the agent cannot open `.env` or `.env.test`. A test setup that loads them gets no values, or fails.

This holds for agents with an OS sandbox (Claude Code and Codex on macOS and Linux, or any agent under `openmoat run`; on Linux `openmoat run --isolate`). Cursor's sandbox cannot deny `.env` inside the workspace, and a hook-only agent's tests can read them. See [Limits](/docs/limits/).

</Aside>

Ways to handle it:

- Keep values tests need that are not secret in a file that is not named `.env*`, such as `config/test.json`.
- Run tests that need real secrets yourself, outside the agent.
- Give the agent a token through the broker instead: [Keep a token from the agent](/docs/keep-tokens-safe/).

### Variables you export

A variable set in the shell you start the agent from is still passed to the programs it runs. The agent cannot print a denied name, but a program it runs (a CLI, a test) can use the value and send it to an allowed host. Do not export production secrets in the shell you run an agent from, or broker them.

### Other gaps

- Only the names listed above count as secrets: a password in `SENTRY_URL` is read unless you deny it.
- An alias of the environment in inline code (`e = os.environ`) is not followed.

More in [Limits](/docs/limits/).
