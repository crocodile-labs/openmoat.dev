<Aside type="note" title="Read this when">

A security reviewer or auditor asks how you control what your coding agent does, and you want records to show them. New in 0.14.0.

</Aside>

<Aside type="caution" title="Evidence, not a certification">

The report lists what OpenMoat recorded about an agent's tool calls on this machine and which framework controls those records relate to. It does not show that any control is met, and using OpenMoat does not make anyone compliant.

</Aside>

## What it does

`openmoat audit evidence` reads the audit log for a time window and reports, per control of three public frameworks, which OpenMoat rules fired, how often by verdict, and sample events:

- OWASP Top 10 for LLM Applications 2025 (`LLM01:2025` … `LLM10:2025`)
- SOC 2 Trust Services Criteria, common criteria CC6 to CC8
- ISO/IEC 27001:2022 Annex A

Run it from your own terminal: an agent's sandbox cannot read the audit log. Nothing is sent anywhere.

## Make a report

<Steps>

1. **Pick a window and write the report**

   ```bash
   openmoat audit evidence --since 2026-10-01 --until 2026-11-01 > evidence-october.md
   openmoat audit evidence --since 30d --format json > evidence.json
   openmoat audit evidence --since 7d --host claude-code --samples 5
   ```

2. **Read a control**

   Each control lists the rule groups that relate to it and the decisions by verdict. Each rule group lists its rules, whether the policy in force has each one, their counts and redacted sample events.

3. **Show the events were not changed**

   The report gives the window's newest event hash. Give the reviewer an export they can check against it:

   ```bash
   openmoat audit export --since 2026-10-01 > window.jsonl
   openmoat audit verify window.jsonl --anchor <the hash from the report>
   ```

</Steps>

| Option | Means |
|---|---|
| `--since` | window start: `all` (default), `today`, `yesterday`, `12h`, `7d`, `2w` or `YYYY-MM-DD` (UTC) |
| `--until` | window end, not included, in the same forms (`2026-11-01` ends before that day); default now |
| `--host` | only one agent's events |
| `--samples` | sample events per rule group and control, 0 to 50 (default 3) |
| `--format` | `text` (Markdown, the default) or `json` (format `openmoat-evidence-v1`) |

## Example

Shortened, for a log of six decisions (hashes cut):

```markdown
# OpenMoat evidence report

Evidence, not a certification. …

- Window: 2026-10-01T00:00:00Z to 2026-11-01T00:00:00Z (UTC, end not included)
- Decisions: 6 (allow 1 · defer 1 · review 1 · deny 3)

## Audit log

- Hash chain: intact over 6 events, head `3f1c…`

## Controls

### OWASP Top 10 for LLM Applications 2025

| Control | Rule groups | Decisions | allow | defer | review | deny |
|---|---|---|---|---|---|---|
| LLM02:2025 Sensitive Information Disclosure | secrets, secret-egress | 2 | 0 | 0 | 0 | 2 |
| LLM03:2025 Supply Chain | packages, mcp | 1 | 0 | 0 | 1 | 0 |
…
```

## What the report holds

- **The statement** that this is evidence, not a certification, in both formats.
- **Decisions in the window**, by verdict.
- **The audit log**: whether the whole hash chain verifies, its head, the window's first and last event ids and the newest event's hash.
- **The policy, lock and protections at the time of the report**: the policy's SHA-256 and whether it is the shipped default; the lock's pinned files, any drift and when it was last pinned (flagged when that is after the window started); each agent's protection level, as `openmoat status` reports it.
- **Controls** and **rule groups**, as above. A default rule the policy in force lacks shows as "cannot fire"; rules the code adds itself show as "built in".
- **Rules that map to no control**: allow rules, the catch-all, your own rules and audit-only rows, so every decision in the window is accounted for.

Sample events are the stored rows, redacted before they were written, as in `openmoat audit export`.

## The frameworks it maps

| Rule group | OWASP LLM 2025 | SOC 2 | ISO/IEC 27001:2022 |
|---|---|---|---|
| `secrets` (`secrets-paths`, `agent-credentials`, `env-secrets`, …) | LLM02 | CC6.1 | A.5.17, A.8.3 |
| `secret-egress` (`token-egress`, `card-egress`, `session-taint`, `push-secret`, …) | LLM02 | CC6.7 | A.5.14, A.8.12 |
| `network` (`default.net`, `cloud-metadata`, proxy rules) | | CC6.6 | A.8.23 |
| `code-execution` (`pipe-to-shell`, `opaque-code`, `session-written-code`, `executables`) | LLM05 | CC6.8 | A.8.7 |
| `packages` (`package-near-miss`) | LLM03 | CC6.8 | A.8.19 |
| `runs-later` (`runs-later`, `persistence`, `shell-rc`, `git-internals`, …) | | CC6.8 | A.8.7 |
| `self-protection` (`kernel-self`, `agent-folders`, `stops-openmoat`) | LLM06 | CC8.1 | A.8.9 |
| `integrity` (`kernel-integrity`, `settings-drift`, `project-settings`) | | CC7.1, CC8.1 | A.8.9 |
| `mcp` (`mcp-server-changed`, `mcp-tool-held`, `mcp-unattributed`) | LLM03 | CC6.8, CC7.1 | A.8.19 |
| `destructive` (`destructive`, `destructive-recoverable`) | LLM06 | | |
| `audit-log` (every recorded event) | | CC7.2 | A.8.15 |

Not mapped, on purpose: LLM01 Prompt Injection (OpenMoat limits what an injected instruction can make the agent do, which is LLM06, but does not detect injection), LLM04, LLM07 to LLM10, and every SOC 2 or ISO control about people, processes or systems other than the agent's tool calls. Control titles in the report are short paraphrases; the frameworks' own texts are the reference.

## Limits

- **State, not history.** The policy, lock and protections are read when you run the report. The audit log does not record which policy decided each call; when the lock was re-pinned after the window started, the report says the policy in force may have differed.
- **Only what reached OpenMoat.** An agent that is not set up, a hook that failed open, a tool outside the hook or a command inside an allowed script is not in the log. Zero denies can mean nothing was attempted or that nothing was checked; the protections table says which agents were checked.
- **Counts are not effectiveness.** A rule that fired shows the rule operated on that call; no number in the report says a control is designed or operating effectively.
- **By rule id.** A custom policy that keeps an id but changes its patterns keeps its mapping; the report shows whether the policy is the shipped default.
- **One machine.** For several machines, export each log and combine them with `openmoat audit report`, which does not map controls.
- **A project's repository policy** is not shown; its rules appear as `repo:<id>` under rules that map to no control.
