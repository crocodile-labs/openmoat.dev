<Aside type="note" title="Read this when">

An MCP server's tools are denied with `mcp-server-changed`, you added a server, or you want its tool descriptions pinned.

</Aside>

**Protects against** an MCP server nobody reviewed (one a cloned repository's `.mcp.json` adds, or a definition a `git pull` changes), a tool whose description changes after you accepted it, and MCP calls that read secrets or reach unlisted hosts.

## What it does

An MCP server runs outside every sandbox, with your permissions, whatever its definition says. A postinstall script, a `git pull` or a cloned repository can change a definition or add one, and a server you accepted can later change what a tool's description tells the model. OpenMoat checks every MCP tool call against your policy, and also holds back servers and tools that nobody has reviewed.

MCP calls are checked by tool name **and** by what their arguments name: `mcp__filesystem__read_file {path: ~/.aws/credentials}` is denied by `secrets-paths` although `safe-mcp` allows the tool, and a `url` argument is checked like any host.

## Example

A cloned repository's `.mcp.json` adds a server. Its tool calls are denied, and the reason ends with what to run:

```text
moat: deny [mcp-server-changed] — …; a person must review it: run `openmoat mcp accept <server>` in a terminal
```

`openmoat doctor` shows the same: ``mcp servers      ✗ …; `openmoat mcp accept` shows it and asks``.

## Server definitions are pinned

`openmoat init` pins each MCP server definition the agents read:

| Agent | Your file | The project's file |
|---|---|---|
| Claude Code | `~/.claude.json` | `.mcp.json` |
| Codex | `config.toml` | `.codex/config.toml` |
| Cursor | `mcp.json` | `.cursor/mcp.json` |
| OpenClaw | `mcp.servers` in `openclaw.json` | |
| GitHub Copilot CLI | `~/.copilot/mcp-config.json` | `.mcp.json`, `.github/mcp.json` |
| pi | `~/.pi/agent/mcp.json` | `.pi/mcp.json` |
| Gemini CLI | `mcpServers` in `settings.json` | `.gemini/settings.json` |

When a definition changes, or a server is added since (a cloned repository's `.mcp.json` included), the tool calls of that server are denied with rule `mcp-server-changed`. The reason names what changed. Other servers and tools keep working, and `openmoat doctor` and `openmoat status` report it.

`openmoat init` pins what it finds the first time. Run again without a terminal (from a script), it pins nothing new: changed and new servers are listed and left for `openmoat mcp accept`.

<Steps>

1. **Review the change, in your own terminal**

   ```bash
   openmoat mcp accept <server>
   ```

   It shows the change key by key, never the value of an `env` or header entry, and asks `[y/N]`. Escape sequences and invisible characters in what a server sends are shown as `?`, so a tool description cannot redraw what you are asked to accept.

2. **Ask the agent to try again**

   The server's tools work again once you accept.

</Steps>

A removed server holds nothing back. A settings file that no longer parses holds back every MCP call of that agent, since it hides which servers it starts.

<Aside type="caution" title="A changed server still starts">

The agent starts its MCP servers when a session begins, before any tool call. OpenMoat refuses the server's tool calls, but it cannot stop the program from starting. To contain what a server does at start, run it with `--sandbox` (below) or run the whole agent with `openmoat run`.

</Aside>

The agent's own writes to these files ask first (`runs-later`), since the agent starts what they name in its next session.

## Pin tool descriptions too

Pinning a definition does not see a server that changes a tool's description later. For that, run a stdio server through `openmoat mcp proxy`. It is opt-in per server:

```bash
openmoat mcp wrap <server>      # one server
openmoat init --mcp-proxy       # every server, at setup
```

`openmoat mcp proxy` sits between the agent and the server and:

- pins each tool's name, title, description, input and output schemas and annotations (such as `readOnlyHint`, which an agent may read to run a call without asking), and every other field of the tool as it is;
- leaves every tool of a server it has not pinned yet out of the tool list, and refuses its calls, naming `openmoat mcp accept <server>`, which shows each tool and asks;
- leaves a changed or new tool out of the tool list, and answers a call to it with an error naming `openmoat mcp accept <server>`; the call never reaches the server;
- records every tool call in the audit log.

`openmoat mcp accept <server>` then shows a diff of what changed. `openmoat mcp wrap` changes only the server's command in your own file (`~/.claude.json`, Cursor's `mcp.json`, Codex's `config.toml`, Copilot CLI's `mcp-config.json`), keeps a backup, and never rewrites a project's file. A server with a change you have not accepted is skipped. Add `--dry-run` to see what it would change.

### Run the server in a sandbox

```bash
openmoat mcp wrap <server> --sandbox
```

The server then runs under `openmoat run`: the sandbox made from your policy, with network only to the hosts the policy allows. Many servers need writes (package caches) or hosts the default policy does not list, so this is a choice per server. `--sandbox` cannot be used for an agent that itself runs under `openmoat run`.

### Undo it

```bash
openmoat mcp unwrap <server>
```

`openmoat uninstall` also puts every wrapped server back as it was.

## Only you accept

`openmoat mcp accept`, `openmoat mcp wrap` and `openmoat mcp unwrap` are denied to agents (`kernel-self`), terminal wrappers included, and refuse to run when an agent started them.

## Good to know

- **First sight is not trusted.** `openmoat mcp proxy` holds back a new server's tools until you accept them. To pin what a server lists the first time instead, set `mcp: { trust_first_sight: true }` in the policy; `openmoat policy lint` warns about it.
- **Not pinned:** prompts, resources and tool results.
- **Upgrading to 0.9.0** pins more fields of each tool, so every tool a wrapped server listed is held once after the upgrade, even unchanged. Run `openmoat mcp accept` once.
- **Not covered by the proxy:** remote (HTTP) servers, Claude Code plugin servers and managed MCP settings.
- **One name, every project.** A changed server in one project of `~/.claude.json` also holds back a server with the same name in another project, until you accept it.

<Aside type="note" title="Upgrading from 0.5.6 or earlier">

A lock from before 0.5.7 has no MCP pins, so nothing is held back until `openmoat init` or `openmoat mcp accept` pins the servers. `openmoat doctor` says so.

</Aside>

## Commands

| Command | What it does | Example |
|---|---|---|
| `openmoat mcp accept [<server>]` | Show a changed or new server, or the tools the proxy holds, key by key, and ask. Terminal only | `openmoat mcp accept github` |
| `openmoat mcp wrap [<server>…] [--sandbox] [--dry-run]` | Run stdio servers through `openmoat mcp proxy`, which pins each tool. Terminal only | `openmoat mcp wrap github --dry-run` |
| `openmoat mcp unwrap [<server>…]` | Point them back at their own command. Terminal only | `openmoat mcp unwrap github` |
| `openmoat init --mcp-proxy` | Wrap every stdio server at setup | `openmoat init --mcp-proxy` |
| `openmoat policy check "<tool>" --kind mcp` | The verdict for an MCP tool name | `openmoat policy check "mcp__github__create_issue" --kind mcp` |
| `openmoat mcp proxy --server <name> [--sandbox] -- <command>` | The wrapper `openmoat mcp wrap` writes; the agent starts it, you do not | |

## Settings

```yaml
allow:
  - id: my-mcp-reads
    mcp: ["mcp__docs__search*"]       # tool names, as mcp__<server>__<tool>
mcp:
  trust_first_sight: false            # default: the proxy holds a new server's tools until you accept them
```

## Limits

- **A changed server still starts**, when the agent starts its session; only its tool calls are refused.
- **Not pinned:** prompts, resources and tool results. **Not covered by the proxy:** remote (HTTP) servers, Claude Code plugin servers and managed MCP settings.
- **An MCP server runs outside every sandbox** unless you wrap it with `--sandbox` or run the agent under `openmoat run`.

More in [Limits](/docs/limits/). The design and its limits: [ADR-026](https://github.com/crocodile-labs/openmoat/blob/main/docs/adr/ADR-026-mcp-server-and-tool-pinning.md).
