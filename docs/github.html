Use GitHub from the agent

git, gh and the GitHub API from an agent: what runs, what asks and what is denied.

Read this when the agent commits, pushes, opens pull requests or reads issues.
The agent runsAnswer
git status, git diff, git add, git commit, git log, git fetch, git pull, git rebaseallow
gh pr view 12, other read-only gh commandsallow
git push origin main, gh pr create --fill, gh api …defer: your agent's prompt
git config core.hooksPath .h, a write into .git/hooksask: git-internals
A write to .github/workflows/ci.yml, .husky/pre-commitask: runs-later, CI or a commit runs it later
git push --force, git push origin :main, git reset --hard, git clean -fdx, git branch -D xdeny: destructive
gh auth token, gh auth status -t, cat ~/.config/gh/hosts.yml, git credential filldeny: they print your token

#Let gh work without handing over the token

gh reads its token from ~/.config/gh or from GH_TOKEN / GITHUB_TOKEN. The agent cannot read the first, so inside the agent gh is not logged in. Broker the token instead:

bash
moat secret add gh                       # once
export GITHUB_TOKEN="$(gh auth token)"   # in your terminal, before starting the agent

gh in the agent then works against api.github.com with a placeholder. The full story: Keep a token from the agent.

#Pushing

A push goes to your agent's prompt, so you see every one. A force push, a push that deletes a remote branch and history-rewriting resets are denied: undoing them is often impossible. If you want to force-push, do it yourself.

Fewer prompts for pull requests

To let the agent open pull requests without asking, allow the command in OpenMoat (moat allow "gh pr create" --always) or use your agent's own "always allow". Read-only gh commands are already allowed.
